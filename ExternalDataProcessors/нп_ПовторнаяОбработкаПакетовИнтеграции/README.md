# Повторная обработка пакетов интеграции (НП)

Внешняя обработка ищет входящие пакеты RMQ в регистре `тн_Интеграция_ЛогСообщений` и повторно загружает выбранные штатным контуром `тн_Интеграция_ERP_УХ.ПолучениеСообщенийRMQ` **без** повторной отметки «доставлено» в RabbitMQ.

Исходники: `ExternalDataProcessors/нп_ПовторнаяОбработкаПакетовИнтеграции/`

## Сборка .epf

1. Конфигуратор **в базе ERP** → **Файл → Открыть** → каталог `нп_ПовторнаяОбработкаПакетовИнтеграции` (файл `нп_ПовторнаяОбработкаПакетовИнтеграции.xml`).
2. **Файл → Сохранить как…** → `нп_ПовторнаяОбработкаПакетовИнтеграции.epf`.

## Использование

- **Файл → Открыть** → `.epf`, либо регистрация в **Дополнительные отчёты и обработки** (вид: дополнительная обработка).
- Укажите период, при необходимости вид сообщения (`catalogEmployees` по умолчанию), ИД, базу-респондент или подстроку (GUID объекта в JSON).
- **Найти** → отметьте строки → **Обработать выбранные**.
- **Показать пакет** выводит `XML_ПакетВходящий` текущей строки; JSON можно вставить в «Текст пакета» и обработать без таблицы.
- Флаг **Поставить в очередь** записывает пакет в `тн_Интеграция_ОчередьОбработкиСообщенийRMQ` вместо немедленной загрузки; дальше его заберёт регламентное задание «Многопоточная обработка сообщений RMQ».

Нужны права на чтение лога интеграции и запись загружаемых объектов. Безопасный режим выключен.

Пакет есть в логе только если у профиля подключения включено `ВестиЛоги`. Если повторная загрузка сотрудников не заполняет `ФизическоеЛицо`, нужна отдельная доработка заполнения в расширении НП — эта обработка только прогоняет тот же контур заново.
