## Context

Заявка **ERP.2026.12**: внешняя ПФ «Накладная на перемещение» для `Документ.ПеремещениеТоваров` по образцу внешних М-11 / МБ-7.

**Типовой контур сегодня:**
- Команда печати: менеджер `Документ.ПеремещениеТоваров`, идентификатор `НакладнаяНаПеремещение`
- Формирование: `СформироватьПечатнуюФормуНакладнойНаПеремещениеТоваров` (не экспортная) — запросы шапки/товаров inline в менеджере
- Макет: `Документ.ПеремещениеТоваров.ПФ_MXL_НакладнаяНаПеремещение` (области: ЗаголовокПеремещение / ЗаголовокВнутренняяПередача, ШапкаТаблицы, Строка, Подвал, Подписи, …)
- Область «Подписи»: статический текст «Отпустил» / «Получил» **без параметров** — типовой код выводит область пустой (`ТабличныйДокумент.Вывести(ОбластьПодписей)` без `Параметры.Заполнить`)

**Данные для кастомизации (уже в конфигурации):**
- `Справочник.Склады.ТекущийОтветственный` → `СправочникСсылка.ФизическиеЛица`
- `Справочник.Склады.ТекущаяДолжностьОтветственного` → строка; хелпер `СкладыСервер.ДолжностьОтветственногоЛицаСклада` (fallback «Кладовщик»)
- `РегистрСведений.Заместители`: измерения `ЗамещаемыйПользователь`, `Заместитель` (`Пользователи`), `ДатаНачала`, `ДатаОкончания` (пустая дата = без ограничения)
- `Справочник.Пользователи.ФизическоеЛицо` — мост ФЛ ↔ пользователь для проверки замещения

**Эталон внешней ПФ:** `ExternalDataProcessors/тн_ПФ_М11_ВнутреннееПотребление`, `тн_ПФ_МБ7_ВнутреннееПотребление`.

**Ограничения:** исходники в `C:\Projects\ERPUH`; код конфигурации — `C:\EDTProjects\uh_np`; стандарты — `Instructions/стандарты-разработки-1с.md`, внешние обработки — `Instructions/внешние-обработки.md`.

## Goals / Non-Goals

**Goals:**
- Внешняя ПФ накладной с регистрацией БСП, назначение — `Документ.ПеремещениеТоваров`
- Типовое содержимое шапки и ТЧ товаров
- Заполнение Отпустил/Получил МОЛ складов с учётом `Заместители` на дату документа
- Устойчивость к пустым МОЛ / отсутствию пользователя / отсутствию замещения

**Non-Goals:**
- Правка типового менеджера / макета в конфигурации
- Скрытие/замена штатной команды «Накладная на перемещение» (показываем обе)
- Замещение процессов согласования УХ за пределами вывода ФИО в ПФ
- Фильтр по хозяйственной операции (печатаем все перемещения, как типовая)

## Decisions

### 1. Внешняя обработка по образцу М-11 / МБ-7

**Решение:** `ExternalDataProcessors/нп_ПФ_НакладнаяНаПеремещение/`, `СведенияОВнешнейОбработке()` + `Печать()`, идентификатор команды `нп_НакладнаяНаПеремещение`, представление «Накладная на перемещение (НП)», `БезопасныйРежим = Ложь`. Форма отладки — по образцу `нп_ПечатьМ11`.

**Почему:** единый поставкиный контур внешних ПФ; не ломает обновления типовой.

### 2. Копия логики формирования + дозаполнение подписей

**Решение:** перенести в модуль объекта логику типовой `СформироватьПечатнуюФормуНакладнойНаПеремещениеТоваров` (запросы шапки/товаров, вывод областей), затем перед выводом «Подписи» заполнять параметры/ячейки своими данными. Типовая функция не экспортная — вызов из внешней обработки невозможен без дублирования.

**Альтернатива отклонена:** правка менеджера документа / расширение `&После` — не соответствует формату «внешняя ПФ».

### 3. Макет: копия типового с параметрами подписей

**Решение:** встроить макет `ПФ_MXL_НакладнаяНаПеремещение` (копия типового) и в области «Подписи» расположить параметры как в `нп_ПечатьМ11`:
- `ДолжностьОтправителя`, `ФИООтправителя`
- `ДолжностьПолучил`, `ФИОПолучил`

Заполнение — через `ОбластьПодписей.Параметры.*` (не программная подмена текста ячеек).

**Почему:** в типовом макете параметров подписей нет; эталон — доработанный `нп_ПечатьМ11`.

### 4. Источник МОЛ

| Поле ПФ | Источник |
|---|---|
| Отпустил (ФИО) | `СкладОтправитель.ТекущийОтветственный`, с учётом замещения |
| Отпустил (должность) | без замещения — должность склада-отправителя; при замещении — кадровые данные заместителя |
| Получил (ФИО) | `СкладПолучатель.ТекущийОтветственный`, с учётом замещения |
| Получил (должность) | без замещения — должность склада-получателя; при замещении — кадровые данные заместителя |

ФИО на печать — `ФизическиеЛицаУТ.ФамилияИнициалыФизЛица(ФизЛицо, ДатаДокумента)`.

### 5. Алгоритм замещения на дату документа

Для физлица МОЛ склада:

1. Найти пользователя(ей): `Пользователи` с `ФизическоеЛицо = МОЛ` (не помеченные на удаление; при нескольких — проверять всех).
2. В `РегистрСведений.Заместители` отобрать записи, где `ЗамещаемыйПользователь` ∈ найденные пользователи и дата документа попадает в период:
   - `ДатаНачала <= ДатаДокумента` ИЛИ `ДатаНачала` пустая;
   - `ДатаОкончания >= НачалоДня(ДатаДокумента)` ИЛИ `ДатаОкончания` пустая.
3. Если есть заместитель — взять **последнего** по `ДатаНачала` (убыв.; при равенстве — по представлению заместителя), получить `Заместитель.ФизическоеЛицо` и вывести его.
4. Если пользователя нет или замещения нет — вывести исходного МОЛ склада.
5. Должность:
   - без замещения — `СкладыСервер.ДолжностьОтветственногоЛицаСклада` (должность склада);
   - при замещении — из `РегистрСведений.ТекущиеКадровыеДанныеСотрудников` по физлицу заместителя (как в М-11/МБ-7); если пусто — fallback на должность склада.
   При пустом ФЛ заместителя — fallback на исходного МОЛ и должность склада.

Пакетный запрос по всем складам документов печати (без query-in-loop).

**Почему не `МодульУправленияПроцессамиУХ.ПолучитьЗаместителей`:** там зашита `ТекущаяДата()`, а нужна дата документа; плюс API заточен под списки согласования, не под печать.

### 6. Имя параметров печати

**Решение:** `ПАРАМЕТРЫ_ПЕЧАТИ_нп_НакладнаяНаПеремещение` (не пересекаться с типовым `ПАРАМЕТРЫ_ПЕЧАТИ_ПеремещениеТоваров_Накладная`).

## Risks / Trade-offs

- [ФЛ без пользователя] → замещение не проверяется, печатается МОЛ склада
- [Несколько заместителей / несколько пользователей на одно ФЛ] → берётся один детерминированный; риск «не того» человека — зафиксировать правило и при необходимости уточнить у заказчика
- [Заместитель без заполненного `ФизическоеЛицо`] → fallback на исходного МОЛ
- [Расхождение макета после обновления УХ] → копия макета потребует ручного переноса
- [Вызов модулей конфигурации] → `БезопасныйРежим = Ложь`
- [Дублирование типового кода печати] → при обновлении УХ сверять дифф менеджера `ПеремещениеТоваров`
