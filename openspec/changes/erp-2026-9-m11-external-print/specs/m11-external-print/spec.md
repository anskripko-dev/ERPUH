## ADDED Requirements

### Requirement: External M-11 print form registration
Система SHALL предоставлять внешнюю печатную форму «Требование-накладная (М-11)» для документа `ВнутреннееПотребление`, регистрируемую через подсистему «Дополнительные отчёты и обработки» (вид — печатная форма).

#### Scenario: Command available on document
- **WHEN** внешняя обработка зарегистрирована в ИБ и пользователь открывает печать документа «Внутреннее потребление»
- **THEN** доступна команда внешней печатной формы М-11 (наименование по ТЗ / согласованное представление)

#### Scenario: Uses current document data
- **WHEN** пользователь формирует печатную форму по документу с актуальными реквизитами и операцией «Списание на расходы»
- **THEN** печатная форма строится по текущим данным объекта документа на момент печати

#### Scenario: Only write-off as expenses operation
- **WHEN** пользователь печатает документ «Внутреннее потребление» с хозяйственной операцией, отличной от «Списание на расходы» (`СписаниеТоваровПоТребованию`)
- **THEN** печатная форма для этого документа не формируется; пользователю выводится сообщение о ограничении

#### Scenario: Mixed selection filtered
- **WHEN** в печать переданы несколько документов, часть с операцией «Списание на расходы», часть с иной операцией
- **THEN** ПФ формируется только по документам «Списание на расходы»; остальные пропускаются с сообщением

### Requirement: Preserve typical goods table
Типовая табличная часть печатной формы М-11 (номенклатура, количество, цена, сумма и прочие колонки типового макета) SHALL оставаться без изменения состава и логики заполнения относительно типового механизма `Обработка.ПечатьМ11` / данных `ПолучитьДанныеДляПечатнойФормыМ11`.

#### Scenario: Typical rows unchanged
- **WHEN** формируется внешняя ПФ по документу с несколькими строками ТЧ «Товары» (не работы)
- **THEN** типовая таблица товаров выводится с тем же набором колонок и правилами заполнения, что и типовая М-11

### Requirement: Header and signature fields from document
Внешняя ПФ SHALL заполнять следующие поля поверх (или вместо пустых подчёркиваний) типового макета:

| Поле ПФ | Источник |
|---|---|
| Отпустил (должность, подпись/ФИО) | `тн_ОтветственныйСотрудник`; должность — из текущих кадровых данных физлица |
| Получил (должность, подпись/ФИО) | `тн_Затребовал`; должность — из текущих кадровых данных физлица |
| Через кого | `тн_ОтветственныйСотрудник` |
| Затребовал | `тн_Затребовал` |
| Разрешил | руководитель организации документа (ответственные лица организации) |

Остальные реквизиты шапки/таблицы SHALL заполняться типовыми механизмами данных М-11 для внутреннего потребления.

#### Scenario: All signature sources filled
- **WHEN** в документе заполнены `тн_ОтветственныйСотрудник` и `тн_Затребовал`, у физлиц есть текущая должность, у организации задан руководитель
- **THEN** в ПФ выводятся ФИО/должность для «Отпустил» и «Получил», представление «Через кого» и «Затребовал», а также руководитель в «Разрешил»

#### Scenario: Missing optional person fields
- **WHEN** один или несколько из `тн_ОтветственныйСотрудник`, `тн_Затребовал`, должности или руководителя не заполнены
- **THEN** печатная форма формируется без ошибок; незаполненные поля выводятся пустыми

### Requirement: Notes section with materials table
В разделе «Примечание» SHALL выводиться дополнительная табличная часть «Материальные ценности» с колонками:

1. Материальные ценности — `Товары.Номенклатура`
2. Статья списания — `Товары.СтатьяРасходов` (статья списания)
3. Аналитика — аналитика строки ТЧ «Товары» (для списания на расходы — `АналитикаРасходов` / соответствующая аналитика статьи)

Количество строк доп. таблицы MUST совпадать с количеством строк ТЧ «Товары» документа. Доп. таблица MUST NOT заменять типовую табличную часть М-11.

#### Scenario: Notes table mirrors goods rows
- **WHEN** в документе N строк ТЧ «Товары»
- **THEN** в «Примечании» выводится таблица из N строк с номенклатурой, статьёй списания и аналитикой каждой строки

### Requirement: Optional commission block
Если существует проведённый документ `тн_ПриказНаКомиссиюПоИнвентаризации` с датой не позже даты списания, подобранный по Организации, Подразделению и Складу документа внутреннего потребления, ПФ SHALL вывести в подвале блок комиссии.

Состав комиссии MUST браться из `РегистрСведений.тн_Комиссии` методом среза последних на дату документа списания (не из табличной части приказа напрямую):

- председатель — отдельной строкой (`СтепеньЧленства = Председатель`)
- каждый член комиссии — отдельной строкой (`СтепеньЧленства = ЧленКомиссии`), в порядке записей регистра

Если председатель или отдельные члены не заполнены, выводятся только заполненные сведения; формирование ПФ не прерывается ошибкой.

#### Scenario: Commission order found
- **WHEN** для организации, подразделения и склада документа найден подходящий приказ на комиссию, и в срезе `тн_Комиссии` на дату списания есть председатель и члены
- **THEN** в подвале ПФ выводятся председатель и члены комиссии по данным регистра

#### Scenario: Commission order missing
- **WHEN** подходящий приказ на комиссию отсутствует
- **THEN** блок комиссии не выводится; остальная ПФ формируется без изменений

#### Scenario: Partial commission data
- **WHEN** приказ найден, но в срезе регистра председатель пуст или часть членов без ФИО
- **THEN** ПФ формируется успешно и выводит только заполненные строки комиссии

#### Scenario: Composition as of write-off date
- **WHEN** состав комиссии в регистре менялся после даты приказа, но до даты списания
- **THEN** в ПФ выводится состав по срезу на дату списания
