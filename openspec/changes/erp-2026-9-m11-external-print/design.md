## Context

Заявка **ERP.2026.9**: внешняя ПФ «Требование-накладная» для `Документ.ВнутреннееПотребление` на базе типовой М-11.

**Типовой контур сегодня:**
- Команда печати: `ВнутреннееПотреблениеЛокализация.ДобавитьКомандыПечати` → менеджер `Обработка.ПечатьМ11`, идентификатор `М11`
- Формирование: `Обработки.ПечатьМ11.СформироватьПечатнуюФормуМ11` → `МенеджерОбъекта.ПолучитьДанныеДляПечатнойФормыМ11`
- Данные для ВП: `ВнутреннееПотреблениеЛокализация.ПолучитьДанныеДляПечатнойФормыМ11` / запрос с итогами по Ссылка, Склад
- Макет: `Обработка.ПечатьМ11.ПФ_MXL_М11` (области: Шапка, ШапкаТаблицы, Подпись, ЗаголовокТаблицы, Строка, Подвал)
- В типовом макете «Через кого / Затребовал / Разрешил» — статический текст с подчёркиваниями (без параметров); «Отпустил» заполняется кладовщиком склада; отдельной области «Примечание» нет

**Кастомизация документа (уже в конфигурации):**
- `тн_ОтветственныйСотрудник`, `тн_Затребовал` — `СправочникСсылка.ФизическиеЛица`
- ТЧ `Товары`: `СтатьяРасходов`, `АналитикаРасходов` (+ др. аналитики)

**Комиссия:** `Документ.тн_ПриказНаКомиссиюПоИнвентаризации` — реквизиты `Организация`, `Подразделение`, `Склад`; ТЧ `ЧленыКомиссии` (`ФИО`, `СтепеньЧленства`, `Должность`); enum `тн_СтепеньЧленстваВКомиссии`: `Председатель`, `ЧленКомиссии`.

**Ограничения:** исходники в `C:\Projects\ERPUH` (ExternalDataProcessors); код конфигурации — `C:\EDTProjects\uh_np`; стандарты — `Instructions/стандарты-разработки-1с.md`, внешние обработки — `Instructions/внешние-обработки.md`; эталон БСП печати — SSL `_ДемоПечатьСчетовНаОплатуПокупателю`.

## Goals / Non-Goals

**Goals:**
- Внешняя ПФ М-11 с регистрацией БСП (вид печатной формы, назначение — `Документ.ВнутреннееПотребление`)
- Переиспользовать типовые данные М-11 для основной таблицы товаров
- Дозаполнить подписи/реквизиты по ТЗ; добавить «Примечание» + опциональную комиссию
- Устойчивость к пустым реквизитам и отсутствию приказа

**Non-Goals:**
- Изменение типовой `Обработка.ПечатьМ11` и типового макета в конфигурации
- Замена/скрытие штатной команды «Требование-накладная (М-11)»
- Печать М-11 для других типов документов (перемещение и т.п.)
- Правки расширений НП/ТН ради этой ПФ (если не потребуются для сборки)

## Decisions

### 1. Внешняя обработка, не правка типовой

**Решение:** отдельная обработка в `ExternalDataProcessors/тн_ПФ_М11_ВнутреннееПотребление/` (или согласованное имя с префиксом `тн_`), регистрация через `СведенияОВнешнейОбработке()` + `Печать()`.

**Почему:** ТЗ явно требует внешнюю ПФ; не ломает обновления типовой М-11.

**Альтернатива:** расширение + переопределение макета — отклонена (не соответствует формату «внешняя ПФ»).

### 2. Данные типовой таблицы — вызов локализации

**Решение:** для основной ТЧ и общей шапки вызывать `ВнутреннееПотреблениеЛокализация.ПолучитьДанныеДляПечатнойФормыМ11` (или эквивалентный публичный путь), затем дозаполнять собственные параметры и доп. области.

**Почему:** ТЗ требует не менять типовую табличную часть и использовать актуальные данные; дублирование сложного запроса цен/курсов рискованно.

**Альтернатива:** полная копия запроса — только если вызов из внешней обработки окажется недоступен в безопасном режиме (тогда `БезопасныйРежим = Ложь` и/или разрешения).

### 3. Собственный макет-копия М-11 с областями дополнений

**Решение:** макет `ПФ_MXL_М11` во внешней обработке — копия типового бланка; добавлены области `ПримечаниеЗаголовок` / `ПримечаниеШапка` / `ПримечаниеСтрока`, `КомиссияЗаголовок` / `КомиссияСтрока` (оформление как у подвала «Отпустил»). Поля «Через кого / Затребовал / Разрешил» — заменой текста в «Подпись»; «Получил» — в ячейки подвала.

**Почему:** нужен вид «как в бланке»; программный вывод таблиц визуально выбивался из формы.

### 4. Должность физлица

**Решение:** должность брать из `РегистрСведений.ТекущиеКадровыеДанныеСотрудников.ТекущаяДолжность` по `ФизическоеЛицо` (и при необходимости отбору по организации документа). Если несколько сотрудников у одного физлица — основной / наиболее приоритетный по правилам ЗУП/ERP, принятым в проекте (зафиксировать в коде одним запросом).

**Почему:** прямо указано в ТЗ («Текущие кадровые данные сотрудников – Должность»).

### 5. Руководитель («Разрешил»)

**Решение:** `ОтветственныеЛицаСервер.СведенияОбОтветственныхЛицах(Организация, "Руководитель", ДатаДокумента)` (или актуальный API модуля) → ФИО руководителя.

**Почему:** в ERP УХ руководитель организации хранится через ответственных лиц, а не как простой реквизит `Организации.Руководитель`. Формулировка ТЗ интерпретируется как «руководитель указанной организации».

### 6. Аналитика в примечании

**Решение:** колонка «Аналитика» = представление `АналитикаРасходов`; если статья подразумевает аналитику активов/пассивов — выводить соответствующую заполненную аналитику строки (приоритет: заполненная аналитика расходов, иначе активов/пассивов).

**Почему:** для операции «Списание на расходы» основной реквизит — `АналитикаРасходов`; в ТЗ поле названо обобщённо «Аналитика».

### 7. Подбор комиссии

**Решение:**
1. Наличие приказа — по `тн_ПриказНаКомиссиюПоИнвентаризации` (Организация + Подразделение + Склад, дата ≤ дата списания).
2. Состав (председатель/члены) — из `РегистрСведений.тн_Комиссии.СрезПоследних` на дату списания с отбором по Организации и `ПодразделениеОрганизации` найденного приказа (не из ТЧ документа).

**Почему:** регистр — актуальный срез состава на дату; ТЧ приказа может не соответствовать состоянию на дату списания.

### 8. Размещение исходников

**Решение:** `C:\Projects\ERPUH\ExternalDataProcessors/...` + инструкция сборки `.epf` в tasks; в EDT/конфигурацию не вшивать без отдельного решения.

## Risks / Trade-offs

- [Вызов модулей конфигурации из внешней ПФ] → `БезопасныйРежим = Ложь` или явные разрешения БСП; проверка на копии ИБ
- [Несколько приказов на одни ключи] → правило «последний по дате»; при необходимости уточнить у заказчика
- [Несколько сотрудников у одного физлица] → один детерминированный выбор должности; риск неверной должности — смягчить отбором по организации
- [Расхождение с типовой М-11 после обновления УХ] → макет-копия потребует ручного переноса изменений типового макета
- [Область «Получил» в типовом подвале слабо параметризована] → явные параметры в копии макета

## Migration Plan

1. Собрать `.epf` из исходников
2. Зарегистрировать в «Дополнительные отчёты и обработки», назначить на `ВнутреннееПотребление`

4. Откат: снять регистрацию внешней обработки (типовая М-11 не затрагивается)
