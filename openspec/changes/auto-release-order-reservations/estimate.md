## Что двигает оценку вверх (пессимистичный 10–12)

- Нет стабильного публичного API обеспечения на сборке → обход через заимствование форм/модулей
- Сложная модель оплаты (авансы без заказа, частично отгружено + частично оплачено)
- Доп. исключения (склады, соглашения, роли) уже в v1
- Обособление всё же нужно снимать через корректировку назначения

## Что двигает вниз (оптимистичный 4–5)

- API обеспечения уже использовался в проекте / есть образец
- Один склад, простая оплата «сумма оплат ≥ сумме заказа»
- Минимум UI (только константы и типовой список РС)

## Не входит в оценку

- v2: срок от даты отгрузки / разные N по соглашению
- Снятие обособленного обеспечения
- Доработка «продлить резерв» на форме заказа
- Покупка и адаптация готового расширения с Infostart (альтернатива make vs buy)
