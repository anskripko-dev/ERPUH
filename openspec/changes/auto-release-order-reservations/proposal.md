## Why

В типовой конфигурации (УТ 11.5 / контур продаж ERP УХ) нет автоматического снятия резерва «через N дней». Резерв держится, пока в строках заказа клиента стоит действие обеспечения (`Резервировать`, `Отгрузить` и т.п.). Склад и менеджеры получают «зависшие» резервы по неоплаченным заказам; нужна регламентная доработка с понятными правилами и журналом.

## What Changes

- Расширение (НП, префикс `нп_`): регламентное задание автоснятия резерва по просроченным заказам клиента
- Настройка срока резерва в днях (константа / РС настроек): срок = **дата заказа + N дней**
- Исключение **полностью оплаченных** заказов; при **частичной** оплате резерв снимается
- Пропуск строк/заказов с **обособленным** обеспечением (v1 не трогает)
- Снятие через типовые механизмы обеспечения: смена действия на `Не обеспечивать` и проведение документа (не прямая запись в регистры)
- Режим dry-run и журнал операций (заказ, строки, причина) для контроля менеджерами
- Оценка трудоёмкости — в `estimate.md`

## Capabilities

### New Capabilities

- `reservation-timeout`: автоматическое снятие резерва с заказов клиента по истечении срока от даты заказа, кроме полностью оплаченных; dry-run и журнал

### Modified Capabilities

- (нет — в `openspec/specs/` ещё нет зафиксированных capabilities по обеспечению/резервам)

## Impact

- Расширение: `C:\EDTProjects\uh_np\uhnp.НП\src\` (префикс `нп_`)
- Типовые объекты (чтение / вызов API, без правки основной конфигурации):
  - `Документ.ЗаказКлиента` (ТЧ товаров, действия обеспечения)
  - механизмы заполнения/изменения обеспечения (API УТ 11.5 / ERP — уточнить по сборке)
  - регистры расчётов/оплаты по заказам (определение полной оплаты)
  - при необходимости — статусы заказа, склады, назначения (обособление)
- Новые объекты расширения: константа/РС срока, РС журнала, регламентное задание, общий модуль
- Не затрагивает: расширение `uhnp.ТН`, обособленное обеспечение (v1 — skip), ручное снятие резерва менеджером
