## Why

Входящие пакеты RMQ (`catalogEmployees` и прочие) после успешной загрузки удаляются из очереди. Повторно прогнать тот же JSON штатной кнопки в логе нет. Нужна внешняя обработка НП, которая находит пакет в `тн_Интеграция_ЛогСообщений` и вызывает контур загрузки без правки расширения ТН.

## What Changes

- Внешняя дополнительная обработка `нп_ПовторнаяОбработкаПакетовИнтеграции`
- Поиск записей лога по периоду, виду сообщения, ИД, тексту пакета
- Повторная обработка выбранных пакетов через `тн_Интеграция_ERP_УХ.ПолучениеСообщенийRMQ` (без повторного IntegrationTicket) либо постановка в `тн_Интеграция_ОчередьОбработкиСообщенийRMQ`

## Capabilities

### New Capabilities
- `reprocess-integration-log-packets`: повторная обработка входящих пакетов интеграции из лога

### Modified Capabilities
- (нет)

## Impact

- Регистр `тн_Интеграция_ЛогСообщений` (чтение `XML_ПакетВходящий`)
- Общий модуль `тн_Интеграция_ERP_УХ.ПолучениеСообщенийRMQ`
- Регистр `тн_Интеграция_ОчередьОбработкиСообщенийRMQ` (опциональная постановка в очередь)
- Типовые объекты и расширение ТН не меняются
