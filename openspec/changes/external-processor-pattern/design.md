# Design: Паттерн внешней обработки

## Context

БСП «Дополнительные отчёты и обработки» поддерживает несколько видов `.epf`. Печатные формы уже есть в репозитории; нужна отдельная фиксация API и практик для **обработок**.

## Goals / Non-Goals

**Goals:**

- Описать виды: доп. обработка, заполнение, связанные объекты
- Зафиксировать типы команд и точки входа (`ВыполнитьКоманду`, форма, параметры БСП)
- Дать копируемый скелет с формой и заготовкой серверной команды
- Отделить от паттерна ПФ

**Non-Goals:**

- Не менять существующие внешние ПФ
- Не описывать внешние отчёты (`.erf`) детально
- Не внедрять конкретную прикладную обработку

## Decisions

1. **Инструкция в репозитории** `Instructions/внешние-обработки.md` — единый источник для агентов (раньше ссылались на внешний `C:\Projects\Instructions\...`).
2. **Шаблон** с видом «дополнительная обработка» по умолчанию и закомментированными альтернативами вида/серверной команды.
3. **Форма в шаблоне** — с `ДополнительнаяОбработкаСсылка`, `ОбъектыНазначения`, примером `ХранилищеНастроек`.
4. ПФ только упоминаются со ссылкой на `тн_ПФ_*`, без дублирования их API.

## Risks

- Имя `ИдентификаторРазделаДополнительныхОбработок` / версия БСП могут отличаться в конкретной поставке УХ — сверять с SSL/конфигурацией при первой сборке.
- UUID шаблона нельзя копировать в прод без замены.
