## Context

Стек ошибки:

```
РегистрСведений.ОтражениеДокументовПоШаблонам.МодульМенеджера(126)
  → ОбработатьКорректировкиПоПараметрам
ТН МодульМенеджера(12) → ПродолжитьВызов
КорректировкиЗначенийПоказателей32(1055) → ВыполнитьОтражениеОбъекта
ТН КорректировкиЗначенийПоказателей32(1230) → ОбработатьДанныеОбъекта
ТН ФормаОтражениеДокумента(13) → ВыполнитьОбработкуМассиваДокументов
```

Сообщение «Ошибка выполнения запроса / В данной транзакции уже происходили ошибки» на строке `Выборка = Запрос.Выполнить().Выбрать()` — вторичное. По стандарту 1С #std783 после исключения во вложенной транзакции любое обращение к БД даёт именно эту ошибку.

Расширение ТН оборачивает отражение во внешнюю транзакцию (тот же приём, что в `тн_НастройкаОтраженияДокументовВУпрУчете`). Типовой `ЗаписатьРабочийОбъект` внутри вызывает `НачатьТранзакцию` / `ОтменитьТранзакцию` и затем пишет протокол — это и маскирует исходную ошибку.

## Goals / Non-Goals

**Goals:**

- Не открывать вложенную транзакцию, если внешняя уже есть.
- Не обращаться к БД после ошибки, пока внешняя транзакция активна.
- Пробрасывать исходное исключение до формы отражения.

**Non-Goals:**

- Исправить исходную прикладную причину по конкретному документу ПНЗК-000011 (закрытый период, шаблон, аналитика) — она станет видна после этого фикса.
- Менять расширение ТН (исходники расширения в этом репозитории отсутствуют).

## Decisions

1. Владение транзакцией определяется флагом `ТранзакцияОткрытаЗдесь` по `ТранзакцияАктивна()` до `НачатьТранзакцию`.
2. Запись протокола после ошибки выполняется только если транзакция уже не активна.
3. В `ОбработатьКорректировкиПоПараметрам` при активной транзакции используется `ВызватьИсключение` без аргументов (повтор исходного исключения).

## Risks / Trade-offs

- Пока внешняя транзакция активна, протокол ошибки не пишется в справочник протоколируемых событий. Исходный текст ошибки при этом доходит до пользователя — это предпочтительнее маскировки.
- Логика применяется ко всем документам отражения по шаблонам, не только к зарплате.
