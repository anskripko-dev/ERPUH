## ADDED Requirements

### Requirement: Opening request document fields
Документ `нп_ЗаявкаНаОткрытиеПериода` SHALL содержать минимум: список организаций, срок действия открытия в днях (K > 0), период «открыть с … по …». Раздел учёта (элемент ПВХ `РазделыДатЗапретаИзменения`) MAY быть пустым. Пустой раздел MUST означать все разделы с типом объекта «Организации».

#### Scenario: Required fields
- **WHEN** пользователь записывает заявку без организаций, без K или без границ периода
- **THEN** запись отклоняется с указанием незаполненных полей

#### Scenario: Optional section empty
- **WHEN** раздел не заполнен
- **THEN** после согласования окно применяется ко всем разделам с типом «Организации» по указанным организациям

#### Scenario: Optional section filled
- **WHEN** указан раздел с типом объекта «Организации»
- **THEN** окно применяется только к этому разделу

### Requirement: No register change until DO approved
Пока состояние согласования в ДО 3 не равно `Согласован`, система MUST NOT менять типовой РС дат запрета из-за этой заявки.

#### Scenario: Draft or in-review does not open period
- **WHEN** заявка записана, отправлена в ДО и состояние `НаСогласовании` или связи с ДО ещё нет
- **THEN** даты в типовом РС не меняются этой заявкой

### Requirement: Window starts at DO approval
Срок K дней MUST отсчитываться от даты установки состояния `Согласован` в `СостоянияСогласованияВДокументообороте` (день согласования — день 1). Окно живо, пока `начало дня сеанса ≤ дата согласования + (K − 1) дней`.

#### Scenario: Five-day window
- **WHEN** заявка согласована 18.08 со сроком 5 дней
- **THEN** окно действует 18.08–22.08 включительно

#### Scenario: Job respects live window
- **WHEN** 20.08 выполняется автосдвиг и окно заявки ещё живо
- **THEN** задание НЕ ставит `сегодня − N` по ключам этой заявки; в типовой РС остаётся отсечка открываемого периода

#### Scenario: Job restores auto-shift after window
- **WHEN** 23.08 окно истекло и по организации включён автосдвиг N
- **THEN** задание записывает `сегодня − N`

### Requirement: Opened period is a cutoff not a hole
Пока окно живо, `ДатаЗапрета` по ключам заявки MUST быть равна дню перед началом открываемого периода (`ПериодС − 1 день`). Всё с датой позже этой отсечки становится редактируемым (типовая семантика БСП: запрет «по дату включительно»). Открыть июль, оставив закрытым более поздний уже закрытый кусок, одной датой MUST NOT требоваться.

#### Scenario: Opening July lowers cutoff
- **WHEN** согласованная заявка открывает период с 01.07 по 31.07
- **THEN** в типовой РС `ДатаЗапрета` = 30.06 по ключам заявки на время окна

### Requirement: Addressee is all users
Заявка MUST писать адресат «для всех пользователей». Персональные строки пользователей механизм заявки MUST NOT перезаписывать (индивидуальная дата БСП по-прежнему перекрывает «для всех»).

#### Scenario: All-users row is updated
- **WHEN** окно применяется
- **THEN** изменяется ключ с адресатом «для всех пользователей»

#### Scenario: Personal row unchanged
- **WHEN** у пользователя есть собственная дата по той же организации
- **THEN** заявка эту строку не меняет

### Requirement: Seamless DO 3 integration
Отправка на согласование и чтение статуса MUST идти через типовой API `ИнтеграцияС1СДокументооборот3*` и регистры связи/состояния. Маршрут согласования настраивается в ДО 3, не дублируется в ERP.

#### Scenario: Start processing in DO 3
- **WHEN** пользователь инициирует согласование заявки и интеграция ДО 3 включена
- **THEN** создаётся/стартует обработка в ДО 3, в ERP появляется связь объекта

#### Scenario: DO unavailable
- **WHEN** веб-сервис ДО недоступен в момент отправки
- **THEN** заявка не считается согласованной, даты не меняются, пользователю выводится ошибка сервиса
