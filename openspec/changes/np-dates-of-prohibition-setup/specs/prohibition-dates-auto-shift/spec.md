## ADDED Requirements

### Requirement: Nightly absolute date equals today minus N
Регламентное задание `нп_СдвигДатЗапретаИзменения` SHALL для каждой включённой настройки `нп_НастройкиАвтосдвигаДатЗапрета` записывать в типовой РС `ДатыЗапретаИзменения` абсолютную `ДатаЗапрета` = начало дня (текущая дата сеанса) минус N дней, если по организации нет действующей заявки на открытие периода. `ОписаниеДатыЗапрета` для этих ключей MUST быть пустым или «произвольная дата» (не относительный вариант БСП).

#### Scenario: Shift without open request
- **WHEN** задание выполняется 18.08, по организации включён автосдвиг N = 10 и нет действующей заявки на открытие
- **THEN** в типовой РС по ключам механизма этой организации `ДатаЗапрета` = 08.08

#### Scenario: Next day moves the cutoff
- **WHEN** на следующий день задание выполняется снова при тех же N и без действующей заявки
- **THEN** `ДатаЗапрета` становится на один день позже (скользящая граница)

### Requirement: Skip keys owned by relative BSP dates
Задание MUST изменять только ключи, которыми владеет этот механизм: адресат «для всех пользователей», `Объект` = организация настройки, `Раздел` — разделы с типом «Организации» (или явный раздел из заявки, пока срок действия открытого периода не истёк). Персональные даты пользователей, касса/склад/сценарии/банковские счета MUST NOT перезаписываться.

#### Scenario: Personal user date is preserved
- **WHEN** в РС есть строка с конкретным пользователем по той же организации
- **THEN** задание её не меняет

### Requirement: Refresh effective dates cache
После записи набор MUST инициировать типовое обновление действующих дат запрета (версия данных / пересчёт БСП), чтобы новые сеансы видели актуальную границу.

#### Scenario: After job users see new cutoff
- **WHEN** задание успешно записало новые даты
- **THEN** последующая проверка запрета изменения использует пересчитанные даты, а не кэш предыдущего дня

### Requirement: Settings are maintained in the auto-shift register
Число дней N и признак включения SHALL задаваться формой списка или записи РС `нп_НастройкиАвтосдвигаДатЗапрета`. Система MUST NOT требовать отдельную обработку бухгалтера или загрузку из Excel для первой очереди.

#### Scenario: Enable auto-shift in register form
- **WHEN** в РС настроек по организации указаны N > 0 и признак «включено»
- **THEN** следующее выполнение задания применяет `сегодня − N` к ключам механизма этой организации (если нет действующей заявки на открытие)

### Requirement: Privileged write without checking the register against itself
Запись дат заданием MUST выполняться привилегированно и MUST NOT отменяться проверкой даты запрета по самому регистру настроек/записей механизма.

#### Scenario: Job runs in a closed period
- **WHEN** текущая дата сеанса попадает в уже закрытый по другим ключам период
- **THEN** задание всё равно записывает новые значения автосдвига
