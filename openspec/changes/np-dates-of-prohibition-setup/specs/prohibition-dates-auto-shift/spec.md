## ADDED Requirements

### Requirement: Nightly absolute date equals today minus N
Регламентное задание `нп_СдвигДатЗапретаИзменения` SHALL для каждой включённой настройки `нп_НастройкиАвтоматическойУстановкиДатЗапрета` записывать в типовой РС `ДатыЗапретаИзменения` абсолютную `ДатаЗапрета` = начало дня (текущая дата сеанса) минус N дней этой настройки, если нет действующей заявки, покрывающей ту же организацию и тот же раздел. `ОписаниеДатыЗапрета` MUST быть пустым или «произвольная дата» (не относительный вариант БСП).

#### Scenario: Shift without open request
- **WHEN** задание выполняется 18.08, по организации для всех пользователей N = 10, раздела нет, заявки нет
- **THEN** в типовой РС по разделам с типом «Организации» и Пользователям «для всех пользователей» `ДатаЗапрета` = 08.08

#### Scenario: Next day moves the cutoff
- **WHEN** на следующий день задание выполняется снова при тех же N и без действующей заявки
- **THEN** `ДатаЗапрета` становится на один день позже (скользящая граница)

#### Scenario: Different N for a user
- **WHEN** по организации для всех N = 10, для пользователя Иванова N = 5, дата сеанса 18.08, заявки нет
- **THEN** для всех пользователей `ДатаЗапрета` = 08.08, для Иванова = 13.08

#### Scenario: Optional section overrides empty section
- **WHEN** есть настройка без раздела N = 10 и настройка на раздел «Учет по МСФО» N = 3, дата сеанса 18.08
- **THEN** по МСФО `ДатаЗапрета` = 15.08, по остальным разделам с типом «Организации» = 08.08

### Requirement: Write only settings-owned records
Задание MUST изменять только записи типового РС, соответствующие настройке: Пользователи настройки, организация настройки, раздел настройки либо все разделы с типом «Организации». Касса, склады, сценарии, банковские счета при пустом разделе MUST NOT заполняться. Записи, которых нет в настройках (в том числе даты только из типовой формы), MUST NOT перезаписываться.

#### Scenario: Typical-form personal date is preserved
- **WHEN** в типовом РС есть строка с пользователем, для которого нет настройки автоматической установки
- **THEN** задание её не меняет

### Requirement: Refresh effective dates cache
После записи набор MUST инициировать типовое обновление действующих дат запрета (версия данных / пересчёт БСП), чтобы новые сеансы видели актуальную границу.

#### Scenario: After job users see new cutoff
- **WHEN** задание успешно записало новые даты
- **THEN** последующая проверка запрета изменения использует пересчитанные даты, а не кэш предыдущего дня

### Requirement: Settings are maintained in the automatic setting register
N, Пользователи (пользователь/группа пользователей), опциональный раздел и признак включения SHALL задаваться формой списка или записи РС `нп_НастройкиАвтоматическойУстановкиДатЗапрета`. Пустое значение Пользователи MUST означать «для всех пользователей». Пустой раздел MUST означать все разделы с типом «Организации». Система MUST NOT требовать отдельную обработку бухгалтера или загрузку из Excel для первой очереди.

#### Scenario: Enable automatic setting in register form
- **WHEN** в РС настроек указаны организация, Пользователи, N > 0 и признак «включено»
- **THEN** следующее выполнение задания применяет `сегодня − N` к соответствующим записям типового РС (если нет действующей заявки по этой организации и разделу)

### Requirement: Privileged write without checking the register against itself
Запись дат заданием MUST выполняться привилегированно и MUST NOT отменяться проверкой даты запрета по самому регистру настроек/записей механизма.

#### Scenario: Job runs in a closed period
- **WHEN** текущая дата сеанса попадает в уже закрытый по другим записям период
- **THEN** задание всё равно записывает новые значения автоматической установки
