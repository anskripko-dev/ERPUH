## ADDED Requirements

### Requirement: Current prohibition dates report
Система SHALL предоставлять отчёт `нп_ДействующиеДатыЗапрета`, показывающий текущее содержимое типового регистра `ДатыЗапретаИзменения` с указанием источника каждой записи:

- автоматическая установка — с указанием настройки и N;
- временно открытый период — с указанием заявки из регистра состояния (первая открывшая граница) и даты окончания действия; дополнительно выводится ответственный по этой заявке;
- установлено вручную — записи типового регистра без комментария `нп_авто`, не подобранные ни к одной включённой настройке и без открытого периода.

Подбор настройки MUST учитывать флажок «Разделы без организации»: пять общих дат `Объект = Раздел` (Банк, Касса, СкладскиеОперации, Бюджетирование, Планирование). Ссылки разделов MUST браться по UUID типовых элементов, не через `ИмяПредопределенныхДанных` / `ЗНАЧЕНИЕ(...Банк)`: эти разделы не предопределённые, иначе отчёт падает с «Предопределенный элемент не существует». Пустые раздел и объект у такой настройки MUST NOT требовать пустой раздел в типовой записи (иначе источник станет «вручную» при комментарии `нп_авто|00006`).

Запись с комментарием `нп_авто` SHALL считаться автоматической, даже если подбор настройки не сработал.

Отчёт MUST NOT выводить вторую пересекающуюся заявку как отдельный источник той же записи типового РС.

Отчёт SHALL поддерживать отбор по объекту, разделу и пользователю.

Отчёт SHALL выводить колонку **Описание даты запрета** читаемым текстом, как на типовой форме БСП (`Конец прошлого месяца (5)`), а не внутреннюю строку `КонецПрошлогоМесяца` + перевод строки + дни. Для скользящей автозаписи — `Скользящее окно`; для комбинированной — оба правила через `; `. Абсолютная ручная дата без описания даёт пустую колонку.

Роль `нп_БазовыеПраваДатЗапрета` MUST NOT давать использование или просмотр отчёта. Отчёт — полные права.

#### Scenario: Basic rights cannot open the report
- **WHEN** пользователь только с ролью `нп_БазовыеПраваДатЗапрета` открывает подсистему дат запрета
- **THEN** отчёт `нп_ДействующиеДатыЗапрета` недоступен

#### Scenario: Sources after mixed operations
- **WHEN** отчёт формируется после сценариев автоустановки, ручных записей и открытых периодов (приёмка 1–15)
- **THEN** источник каждой записи определён корректно; для открытых периодов выведен ответственный

#### Scenario: Filter by object and user
- **WHEN** пользователь задаёт отбор по организации и пользователю
- **THEN** в отчёте остаются только записи, соответствующие отбору

#### Scenario: Overlapping second request not listed
- **WHEN** по одной комбинации действуют две согласованные заявки с пересекающимися сроками
- **THEN** в отчёте у записи типового РС один источник «временно открытый период» с первой заявкой из регистра состояния; вторая заявка отдельной строкой источника не показывается

#### Scenario: Relative description is shown
- **WHEN** в типовом РС есть относительная автозапись с внутренним `ОписаниеДатыЗапрета` (`КонецПрошлогоМесяца` + дни разрешения)
- **THEN** отчёт показывает «Конец прошлого месяца (5)» рядом с датой запрета, а не сырое поле БСП

#### Scenario: Sliding and combined descriptions
- **WHEN** автозапись скользящая или комбинированная (типовое `ОписаниеДатыЗапрета` пустое)
- **THEN** отчёт показывает «Скользящее окно» и/или относительное правило из подобранной настройки

#### Scenario: Non-org flag rows are automatic
- **WHEN** включена настройка с флажком «Разделы без организации» и задание записало Банк/Касса/Склад/сценарии с комментарием `нп_авто|00006`
- **THEN** источник этих строк — «Автоматическая установка», не «Установлено вручную»

#### Scenario: Report does not resolve sections as predefined
- **WHEN** пользователь нажимает «Сформировать»
- **THEN** отчёт не обращается к предопределённым `РазделыДатЗапретаИзменения.Банк` и не показывает «Предопределенный элемент не существует»
