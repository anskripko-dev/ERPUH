## Why

Типовой механизм БСП «Даты запрета изменения» закрывает период абсолютной датой, которую бухгалтерия холдинга ежедневно переносит вручную. Скользящей границы «сегодня минус N дней» в типовых относительных вариантах нет. Временное открытие уже закрытого периода делается администратором по устной просьбе, без фиксации срока и без согласования в 1С:Документообороте. Нужна автоматическая установка границы, заявка с бесшовным согласованием в ДО 3 и отчёт с указанием источника каждой записи.

Основание: заявка **ERP.2026.14**, редакция 2 от 20.08.2026 (инициатор — Лукьянов Евгений, бухгалтерия холдинга). Текст заявки: корневой файл `ERP.2026.14 Заявка на доработку 1С ERP УХ (ред. 2)_1.docx`, выжимка — `tz-extract.txt`.

## What Changes

- Регистр настроек `нп_НастройкиАвтоматическойУстановкиДатЗапрета`: пользователь/группа, раздел, объект, способ расчёта (скользящее N / относительная дата БСП / оба), признак «Включено». Форма с каскадом от первого поля: сначала организация — только орг. разделы; сначала раздел без орг. — организация недоступна, появляется объект раздела (Банк без счёта = все счета всех организаций, с предупреждением); организация без раздела = 18 орг. разделов (банк не входит); пустые организация и раздел = общая дата адресата. Справа список документов раздела.
- Регламентное задание `нп_СдвигДатЗапретаИзменения` (ежедневно 23:00): сначала возврат истёкших открытых периодов, затем актуализация автозаписей типового РС `ДатыЗапретаИзменения`. Чисто относительные даты пишутся типовым `ОписаниеДатыЗапрета` и на лету считает БСП; скользящие и комбинированные — абсолютная дата (для комбинированных — максимум двух). Ручные записи типовой формы не изменяются.
- Документ `нп_ЗаявкаНаОткрытиеПериода`: организация в шапке; без таблицы разделов — общая дата адресата; раздел и объект — только роль `нп_УказаниеРазделовИОбъектовЗаявки` (сначала раздел, затем объект своего типа). После `Согласован` в типовой РС пишется отсечка «Период с минус 1 день»; по истечении K дней граница возвращается. «Закрыть период досрочно» не гасится связью с ДО.
- РС `нп_СостояниеОткрытыхПериодов` (в командном интерфейсе): прежняя дата, срок действия, заявка-основание. Пока запись действует, автоматическая установка эту комбинацию не перезаписывает. Запись программная.
- Отчёт `нп_ДействующиеДатыЗапрета`: содержимое типового регистра с источником (автоустановка / открытый период / вручную).
- Отдельная подсистема `нп_ДатыЗапретаИзменения` в **отдельном** расширении с тем же именем; после теста объекты переносятся в расширение НП.
- Константа получателей уведомлений с формой настройки.
- Типовые объекты, подписки проверки и формы ТН **не изменяются**. Взаимодействие — только запись и удаление записей типового РС по правилам заявки.

## Capabilities

### New Capabilities

- `prohibition-dates-auto-shift`: автоматическая установка дат запрета — скользящее «сегодня минус N» и/или типовое `ОписаниеДатыЗапрета`; без разделов — общая дата адресата
- `period-opening-request`: заявка на временное открытие периода с согласованием в ДО 3, регистром состояния и гарантированным возвратом границы
- `prohibition-dates-current-report`: отчёт по действующим датам запрета с указанием источника записи

### Modified Capabilities

- (нет — в `openspec/specs/` нет зафиксированных capabilities по датам запрета)

## Impact

- Отдельное расширение `нп_ДатыЗапретаИзменения` (`Extensions/нп_ДатыЗапретаИзменения/`). После приёмки объекты переносятся в `uhnp.НП`.
- Подсистема `нп_ДатыЗапретаИзменения` — все новые объекты, в командном интерфейсе.
- Типовой РС `ДатыЗапретаИзменения` — запись/удаление по комбинациям из настроек и заявок; проверка `ПередЗаписью` БСП не меняется.
- Бесшовка ДО 3: `ИнтеграцияС1СДокументооборот3`, `ОбъектыИнтегрированныеС1СДокументооборотом`, `СостоянияСогласованияВДокументообороте`, обработчик `ПриИзмененииСостоянияСогласования`. Печатная форма заявки присоединяется правилом интеграции; все реквизиты и ТЧ в ДО не маппятся.
- Роль `нп_БазовыеПраваДатЗапрета`: документ заявки и отчёт. Роль `нп_УказаниеРазделовИОбъектовЗаявки`: показать в заявке раздел и объект. Регистр настроек и константа — только полные права.
- Не затрагивает: расширение ТН, лаунчер `нп_ОткрытиеДатЗапретаИзменения`, формы `тн_*` на типовом РС.
- Вне объёма: вид документа / шаблон процесса ДО 3 (настройка до приёмки), новый относительный вариант БСП, «дырка» в середине закрытого периода.

Предыдущий черновик OpenSpec (PR #6, ветка `cursor/np-dates-of-prohibition-setup-381e`) опирался на более узкую постановку (только организации, без регистра состояния, без отчёта, без закрытого перечня разделов). Этот change заменяет ту постановку редакцией 2 заявки.

## Решения по открытым вопросам (27.08.2026)

1. `УчетПоМСФО` — в разворачивании по организации без раздела, как «Продажи».
2. Вторая пересекающаяся заявка в отчёте — не показывать.
3. Чтобы заполнить заявку, полные права не нужны: достаточно `нп_БазовыеПраваДатЗапрета` (+ права ДО на отправку).
4. Получатели уведомлений — константа и форма настройки константы.
5. Вопрос был про сценарий приёмки №12 **той же** ERP.2026.14: возврат границы без автоустановки; пользователь в документе обязателен.

Перепроектирование (после уточнений): относительные даты — типовое `ОписаниеДатыЗапрета`; без указанных разделов — общая дата адресата; комбинированное правило кладовщиков — одна абсолютная дата (максимум двух); организация в шапке заявки; раздел/объект только у новой роли; на форме настроек список документов раздела; на пути Банк / касса / склад поле организации скрыто; досрочное закрытие не гасится связью с ДО. Открытые вопросы 7 и 9 — в `design.md`. Реализацию не начинать до согласования.
