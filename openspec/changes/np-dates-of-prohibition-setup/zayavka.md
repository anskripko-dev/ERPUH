# Заявка на доработку

**Номер заявки:** ERP.2026.14

**Дата регистрации:** 19.08.2026

**Конфигурация:** 1С:ERP. Управление холдингом, 3.2.8.25 (режим совместимости 8.3.27)

**Место реализации:** расширение `НП` (префикс `нп_`)

**Тема:** автосдвиг дат запрета изменения и заявка на открытие периода

**Инициатор:** бухгалтерия холдинга

---

## 1. Текущая ситуация

Типовой механизм БСП «Даты запрета изменения» закрывает период: объекты с датой не позднее установленной границы записывать нельзя. Для организаций граница задаётся абсолютной датой. Эту дату приходится регулярно переносить вручную.

Отдельной заявки на временное открытие уже закрытого периода с согласованием в 1С:Документооборот 3 в типовой конфигурации нет.

Типовая проверка даты запрета при записи объектов работает и изменяться не должна.

---

## 2. Цель доработки

1. Автоматически сдвигать абсолютную дату запрета по правилу «сегодня минус N дней» без ежедневной ручной правки типового регистра.
2. Дать возможность временно открыть уже закрытый период по заявке с бесшовным согласованием в 1С:Документооборот 3.

---

## 3. Требуемые изменения

### 3.1. Автосдвиг дат запрета

Ввести настройки автосдвига (регистр сведений `нп_НастройкиАвтосдвигаДатЗапрета`): организация, Пользователи (пользователь/группа пользователей), раздел учёта (необязательно), число дней N, признак включения.

Пустое значение Пользователи означает «для всех пользователей». Пустой раздел означает все разделы учёта с типом объекта «Организации».

Регламентное задание `нп_СдвигДатЗапретаИзменения` записывает в типовой регистр сведений `ДатыЗапретаИзменения` абсолютную дату: начало дня текущей даты сеанса минус N дней настройки.

Для одной организации допускается несколько настроек с разным N: по Пользователям (пользователь/группа пользователей) и, при необходимости, по разделу учёта.

Изменяются только записи типового регистра, которые есть в настройках автосдвига. Даты, заданные только в типовой форме, не перезаписываются. При пустом разделе не заполняются касса, склады, сценарии и банковские счета.

### 3.2. Заявка на открытие периода

Ввести документ `нп_ЗаявкаНаОткрытиеПериода`: организации, срок действия открытого периода в днях (K), период «с» и «по», раздел учёта (необязательно).

Согласование выполняется штатными средствами бесшовной интеграции с 1С:Документооборот 3. Пока заявка не согласована, типовой регистр не изменяется.

После состояния «Согласован»:

- срок действия открытого периода отсчитывается от даты согласования (день согласования - день 1);
- в типовой регистр записывается отсечка «Период с минус 1 день» по организациям, разделу и Пользователям из настроек автосдвига;
- если настроек по организации нет, записывается «для всех пользователей».

Пока срок действия открытого периода не истёк, автосдвиг эти записи не перезаписывает. После истечения срока при включённом автосдвиге восстанавливается своё «сегодня минус N» каждой настройки.

На форме заявки необходимо пояснение: отсечка БСП откроет всё после даты «Период с минус 1 день», а не только выбранный месяц.

---

## 4. Вне рамок настоящей заявки

Постоянно:

1. Изменение типовых подписок и модулей проверки даты запрета.
2. Новый относительный вариант БСП вида «прошло N дней».
3. Открытие только середины закрытого диапазона (одной датой БСП это невозможно).
4. Правки форм расширения ТН.

Отложено (возможен возврат отдельной заявкой):

5. Форма бухгалтера без прав на весь типовой регистр.
6. Массовая загрузка из Excel.

---

## 5. Ожидаемый результат

1. Ночью абсолютная дата запрета сама сдвигается на один день при неизменном N.
2. Разные N могут действовать для разных Пользователей (пользователь/группа пользователей) и разделов учёта одной организации.
3. Согласованная заявка временно открывает период на K дней, затем граница возвращается к автосдвигу.
4. Типовая проверка периода при записи документов и справочников не меняется.

Подробные правила, алгоритмы и критерии приёмки - в техническом задании к заявке ERP.2026.14.
