## Context

В ERP УХ 3.2.8.25 даты запрета — подсистема БСП. Проверка на записи уже работает. Хранение — РС `ДатыЗапретаИзменения` (измерения `Раздел`, `Объект`, `Пользователь`; ресурс `ДатаЗапрета`; `ОписаниеДатыЗапрета` для относительных вариантов).

Отсечка БСП односторонняя: запрещено всё с датой ≤ `ДатаЗапрета`. Произвольная дата не имеет отсрочки; относительные даты сдвигаются сами, но с потолками дней и привязкой к месяцу/кварталу.

В дампе уже есть формы ТН на типовом РС (`тн_УстановитьДатуЗапретаДляСпискаОрганизаций`, `тн_ИзменитьДатыЗапретаПоОрганизации`) — массовая установка из подбора, только с правами на весь регистр. Их не копируем и не правим.

Бесшовка ДО 3 в конфигурации есть (тот же контур, что у `нп_КонтрольПроведенияПоДО`).

Код — расширение `uhnp.НП`, префикс `нп_`. Дамп типовой конфигурации: ветка `uhnp-code-snapshot`.

Первая очередь: автосдвиг и заявка через ДО 3. Форма бухгалтера без прав на весь РС и загрузка из Excel отложены.

## Goals / Non-Goals

**Goals:**

- Держать абсолютную границу как скользящее `сегодня − N` регламентом
- Открывать уже закрытый период заявкой с согласованием в ДО 3 на K дней, записывая более раннюю отсечку в **тот же** типовой РС
- Не менять типовую проверку `ПередЗаписью`

**Non-Goals (сейчас; возможный возврат):**

- Форма бухгалтера `нп_УстановкаДатЗапретаИзменения` и роль `нп_УстановкаДатЗапретаПоОрганизациям` (установка дат без прав на весь РС)
- Массовая загрузка из Excel
- Серверная проверка «своих» организаций при интерактивной записи в типовой РС

**Non-Goals (постоянно):**

- Новый относительный вариант БСП («прошло N дней») в `ОписаниеДатыЗапрета`
- Дырка в середине закрытого диапазона (июль открыт, начало августа закрыто) — одной датой БСП нельзя
- Перезапись дат, которых нет в настройках автосдвига; заполнение кассы, складов, сценариев, банковских счетов при пустом разделе
- Регистрация РС в типовом списке «Загрузка данных из файла»
- Правки форм ТН и лаунчера `нп_ОткрытиеДатЗапретаИзменения`
- Согласование через подсистему УХ вместо ДО 3

## Decisions

### 1. Эффективная дата только в типовом РС

**Решение:** проверка БСП не трогается. Заявка и автосдвиг меняют `ДатаЗапрета` в записях типового РС. Срок K и период «с…по…» хранятся в документе заявки, не в измерениях БСП.

**Почему:** отдельный РС исключений потребовал бы `ПередПроверкойЗапретаИзменения`. Одно значение на запись: пока срок действия открытого периода не истёк — отсечка `ПериодС − 1 день`, потом снова `сегодня − N`.

**Альтернатива:** атрибуты расширения на типовом РС (`нп_Заявка`). Не нужны, если задание читает согласованные заявки.

### 2. Записи, которые изменяет доработка

**Решение:** в типовой РС пишутся строки: `Объект` = организация; `Пользователь` = адресат настройки («для всех», группа или пользователь); `Раздел` = раздел настройки или заявки, а если пуст — все разделы ПВХ с типом `СправочникСсылка.Организации`. N задаётся на сочетание организация + адресат + раздел.

**Почему:** так устроен типовой регистр. Разные пользователи, группы и разделы учёта могут иметь своё N. Пустой раздел не трогает кассу, склады, сценарии, банковские счета. Строки, которых нет в настройках, не меняем: иначе затрём даты, заданные только в типовой форме.

**Альтернатива:** только «для всех пользователей» и все разделы сразу. Не подходит: нужен индивидуальный сдвиг и опциональный разрез по разделу.

### 3. Срок действия открытого периода от даты согласования ДО

**Решение:** день 1 = дата `Согласован` в `СостоянияСогласованияВДокументообороте`. Срок действия открытого периода: с даты согласования по `дата согласования + (K − 1)` включительно. Несогласованная заявка РС не пишет.

**Почему:** иначе согласование на 4-й день съедает срок. Задание каждую ночь: если срок действия открытого периода ещё не истёк — не ставить `сегодня − N` в покрытые заявкой записи; иначе автосдвиг.

### 4. Настройки и заявка без бухгалтерской обработки

**Решение:** N задаётся формой списка/записи РС `нп_НастройкиАвтосдвигаДатЗапрета`. Заявка создаётся из формы документа. Отдельная обработка и Excel не входят в первую очередь. Запись в типовой РС из пользовательского сеанса бухгалтера не делается: пишет регламентное задание и серверная логика после `Согласован`.

**Почему:** убраны права бухгалтера на установку дат и загрузка из файла; их можно вернуть отдельным изменением, не ломая ключи механизма.

**Альтернатива:** оставить обработку только как оболочку над РС и документом. Сейчас лишняя.

### 5. Объекты в расширении НП

**Решение:** документ, РС настроек, задание, модуль `нп_ДатыЗапретаИзменения` — в `uhnp.НП`. Права на новые объекты — через типовые профили / полные права; отдельная роль «установка дат по своим организациям» не вводится.

**Почему:** документ нужен как ссылка для бесшовки ДО 3. Настройки автосдвига заполняет тот, кто администрирует даты запрета.

### 6. Источник статуса заявки — регистр ДО

**Решение:** как в контроле проведения: связь `ОбъектыИнтегрированныеС1СДокументооборотом` + `СостоянияСогласованияВДокументообороте`. Задание не ходит в веб-сервис. Отправка — `ИнтеграцияС1СДокументооборот3.НачатьОбработку`.

## Risks / Trade-offs

- **[Риск] Дата пользователя в типовой форме перекрывает «для всех»** → индивидуальный сдвиг задаётся отдельной настройкой на пользователя или группу; заявка пишет те же адресаты, что в настройках.
- **[Риск] Открытие июля открывает и более поздний закрытый кусок** → ограничение БСП; пояснение на форме заявки.
- **[Риск] Задание затрёт чужую относительную дату** → писать только записи из настроек автосдвига, не все строки организации.
- **[Риск] Привилегированная запись заданием** → аудит в журнале регистрации; не выдавать интерактивную запись типового РС через новую роль.
- **[Риск] Кэш действующих дат БСП** → после набора вызывать типовое обновление версии дат запрета.
- **[Риск] Маршрут ДО не настроен** → заявка не согласуется; даты не меняются (безопасный отказ).
- **[Риск] Без бухгалтерской формы массово завести N неудобно** → приемлемо для первой очереди; Excel и форма бухгалтера отложены.

## Migration Plan

1. Поставить расширение НП.
2. Заполнить `нп_НастройкиАвтосдвигаДатЗапрета` по организациям (форма регистра).
3. Включить регламентное задание в копии, сверить ключи с эталоном, затем в рабочей базе.
4. В ДО 3 завести вид документа / правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`.
5. Откат: выключить задание; записи типового РС остаются как последние абсолютные даты (ручная правка админом при необходимости).

## Open Questions

- Включать ли раздел «Банк» (объект = БС организации) в пустой раздел заявки? Первая очередь: нет.
- Проведение документа заявки vs только запись: достаточно записи + статуса ДО; проведение не обязательно для бесшовки.
- Кто создаёт заявку без отдельной бухгалтерской роли: пользователи с правами на документ расширения / полные права. Уточнить профиль при внедрении.
