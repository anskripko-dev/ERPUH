## Context

В ERP УХ 3.2.8.25 даты запрета — подсистема БСП. Проверка на записи уже работает. Хранение — РС `ДатыЗапретаИзменения` (измерения `Раздел`, `Объект`, `Пользователь`; ресурс `ДатаЗапрета`; `ОписаниеДатыЗапрета` для относительных вариантов).

Отсечка БСП односторонняя: запрещено всё с датой ≤ `ДатаЗапрета`. Произвольная дата не имеет отсрочки; относительные даты сдвигаются сами, но с потолками дней и привязкой к месяцу/кварталу.

В дампе уже есть формы ТН на типовом РС (`тн_УстановитьДатуЗапретаДляСпискаОрганизаций`, `тн_ИзменитьДатыЗапретаПоОрганизации`) — массовая установка из подбора, не из Excel, и только с правами на весь регистр. Их не копируем и не правим.

Бесшовка ДО 3 в конфигурации есть (тот же контур, что у `нп_КонтрольПроведенияПоДО`).

Код — расширение `uhnp.НП`, префикс `нп_`. Дамп типовой конфигурации: ветка `uhnp-code-snapshot`.

## Goals / Non-Goals

**Goals:**

- Дать бухгалтерам установку дат по своим организациям без роли на весь РС
- Массово загружать организации из Excel
- Держать абсолютную границу как скользящее `сегодня − N` регламентом
- Открывать уже закрытый период заявкой с согласованием в ДО 3 на K дней, записывая более раннюю отсечку в **тот же** типовой РС
- Не менять типовую проверку `ПередЗаписью`

**Non-Goals:**

- Новый относительный вариант БСП («прошло N дней») в `ОписаниеДатыЗапрета`
- Дырка в середине закрытого диапазона (июль открыт, начало августа закрыто) — одной датой БСП нельзя
- Перезапись персональных дат пользователей, кассы, складов, сценариев, банковских счетов при пустом разделе
- Регистрация РС в типовом списке «Загрузка данных из файла» (только справочники)
- Правки форм ТН и лаунчера `нп_ОткрытиеДатЗапретаИзменения`
- Согласование через подсистему УХ вместо ДО 3

## Decisions

### 1. Эффективная дата только в типовом РС

**Решение:** проверка БСП не трогается. Заявка и автосдвиг меняют `ДатаЗапрета` на ключах механизма. Срок K и период «с…по…» хранятся в документе заявки, не в измерениях БСП.

**Почему:** отдельный РС исключений потребовал бы `ПередПроверкойЗапретаИзменения`. Одно значение на ключ: пока окно живо — отсечка `ПериодС − 1 день`, потом снова `сегодня − N`.

**Альтернатива:** атрибуты расширения на типовом РС (`нп_Заявка`). Не нужны, если задание читает согласованные заявки.

### 2. Ключи механизма

**Решение:** адресат — «для всех пользователей»; `Объект` — организация; `Раздел` — разделы ПВХ с `ТипыОбъектов`, содержащими `СправочникСсылка.Организации`, либо один выбранный раздел заявки/Excel.

**Почему:** совпадает с массовой формой ТН. Касса/склад/сценарии/БС — другие типы; в MVP не трогаем. Персональная дата БСП перекрывает «для всех» — документируем, не ломаем.

### 3. Окно заявки от даты согласования ДО

**Решение:** день 1 = дата `Согласован` в `СостоянияСогласованияВДокументообороте`. Окно: `[дата согласования; дата согласования + K − 1]`. Несогласованная заявка РС не пишет.

**Почему:** иначе согласование на 4-й день съедает срок. Задание каждую ночь: живое окно → не ставить `сегодня − N` по ключам заявки; иначе автосдвиг.

### 4. Excel — обработка, не типовой список справочников

**Решение:** команда на `нп_УстановкаДатЗапретаИзменения`; разбор через табличный документ / API `ЗагрузкаДанныхИзФайла*` без добавления РС в `ПриОпределенииСправочниковДляЗагрузкиДанных`.

**Почему:** типовая загрузка — только справочники. Колонки: организация (обяз.), N (автосдвиг), дата (разовая абсолютная), раздел (опц.).

### 5. Форма и объекты в расширении НП

**Решение:** обработка, документ, РС настроек, задание, роль, модуль `нп_ДатыЗапретаИзменения` — в `uhnp.НП`. Обработку можно собрать в `.epf` для `ExternalDataProcessors/`. Запись в типовой РС — привилегированно после серверной проверки списка организаций пользователя.

**Почему:** роль на весь РС не выдаём; RLS типового регистра для «своих» организаций недостаточен (там ещё пользователи и разделы). Документ нужен как ссылка для бесшовки ДО 3.

**Альтернатива:** только внешняя обработка без документа — согласование в ДО не к чему привязать.

### 6. Источник статуса заявки — регистр ДО

**Решение:** как в контроле проведения: связь `ОбъектыИнтегрированныеС1СДокументооборотом` + `СостоянияСогласованияВДокументообороте`. Задание не ходит в веб-сервис. Отправка — `ИнтеграцияС1СДокументооборот3.НачатьОбработку`.

## Risks / Trade-offs

- **[Риск] Персональные даты не открываются заявкой** → в инструкции: для участников автосдвига не держать личные строки; иначе отдельная доработка.
- **[Риск] Открытие июля открывает и более поздний закрытый кусок** → ограничение БСП; пояснение на форме заявки.
- **[Риск] Задание затрёт чужую относительную дату на том же ключе** → писать только ключи, уже созданные механизмом / настройками автосдвига, не все строки организации.
- **[Риск] Привилегированная запись** → обязательная серверная проверка организации; аудит в журнале регистрации.
- **[Риск] Кэш действующих дат БСП** → после набора вызывать типовое обновление версии дат запрета.
- **[Риск] Маршрут ДО не настроен** → заявка не согласуется; даты не меняются (безопасный отказ).

## Migration Plan

1. Поставить расширение НП, назначить роль бухгалтерам, не давать `ДобавлениеИзменениеДатЗапретаИзменения`.
2. Заполнить `нп_НастройкиАвтосдвигаДатЗапрета` (форма или Excel) по организациям.
3. Включить регламентное задание в копии, сверить ключи с эталоном, затем в рабочей базе.
4. В ДО 3 завести вид документа / правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`.
5. Откат: выключить задание и константу/флаг механизма; записи типового РС остаются как последние абсолютные даты (ручная правка админом при необходимости).

## Open Questions

- Список «своих» организаций бухгалтера: ответственные лица, RLS организаций, или отдельный РС ответственных? До реализации — ответственные лица / доступные организации по правам чтения справочника.
- Включать ли раздел «Банк» (объект = БС организации) в пустой раздел заявки? MVP: нет.
- Проведение документа заявки vs только запись: достаточно записи + статуса ДО; проведение не обязательно для бесшовки.
