# Техническое задание

**Тема:** установка дат запрета изменения по организациям (массовая загрузка, автосдвиг, заявка на открытие периода)

**Конфигурация:** 1С:ERP. Управление холдингом, 3.2.8.25 (режим совместимости 8.3.27)

**Место реализации:** расширение `НП` (префикс `нп_`)

**Дата:** 18.08.2026

**Связанные артефакты:** OpenSpec-change `np-dates-of-prohibition-setup` (`proposal.md`, `design.md`, `specs/`, `tasks.md`)

---

## 1. Общие сведения

### 1.1. Основание

Необходимость упростить для бухгалтерии холдинга работу с типовым механизмом БСП «Даты запрета изменения»: массовая установка по списку организаций, скользящая абсолютная граница «сегодня минус N дней», согласованное временное открытие уже закрытого периода, работа без прав администратора на весь регистр.

### 1.2. Назначение

Доработка предназначена для установки и сопровождения дат запрета изменения по организациям без изменения типовой проверки периода при записи объектов.

### 1.3. Пользователи

| Роль в процессе | Действия |
|---|---|
| Бухгалтер (роль `нп_УстановкаДатЗапретаПоОрганизациям`) | форма установки, Excel, создание заявки по своим организациям |
| Согласующий в 1С:Документооборот 3 | согласование заявки на открытие периода |
| Администратор дат запрета (типовые роли РС) | полный регистр и типовая форма (без изменений) |
| Регламентное задание | ночной пересчёт абсолютных дат |

### 1.4. Вне рамок настоящей доработки

1. Изменение типовых подписок и модулей проверки даты запрета (`ПередЗаписью`).
2. Новый относительный вариант БСП вида «прошло N дней» в `ОписаниеДатыЗапрета`.
3. «Дырка» в середине закрытого диапазона (например, открыт только июль при уже закрытом начале августа). Одной датой БСП это невозможно: запрещено всё с датой ≤ `ДатаЗапрета`.
4. Перезапись персональных дат пользователей, а также разделов «Касса», «Складские операции», «Бюджетирование», «Планирование», «Банк» (банковские счета) при пустом разделе.
5. Включение регистра `ДатыЗапретаИзменения` в типовой список «Загрузка данных из файла» (типовая загрузка работает только со справочниками).
6. Правки форм расширения ТН (`тн_УстановитьДатуЗапретаДляСпискаОрганизаций`, `тн_ИзменитьДатыЗапретаПоОрганизации`) и обработки `нп_ОткрытиеДатЗапретаИзменения`.
7. Согласование через подсистему согласования УХ вместо 1С:Документооборот 3.

## 2. Характеристика объекта автоматизации

### 2.1. Типовой механизм

Даты запрета хранятся в регистре сведений `ДатыЗапретаИзменения`.

| Измерение / ресурс | Назначение |
|---|---|
| `Раздел` | раздел учёта (ПВХ `РазделыДатЗапретаИзменения`) |
| `Объект` | организация (для разделов с типом объекта «Организации») |
| `Пользователь` | пользователь либо значение «для всех пользователей» |
| `ДатаЗапрета` | граница: запрещено изменение объектов с датой ≤ этой границы |
| `ОписаниеДатыЗапрета` | относительный вариант БСП либо произвольная дата |

Проверка односторонняя. Произвольная абсолютная дата не имеет отсрочки (`КоличествоДнейРазрешения` = 0).

### 2.2. Принцип настоящей доработки

Эффективная отсечка по-прежнему хранится **только** в типовом регистре. Новые объекты расширения задают, **какие** абсолютные значения туда записывать и **когда**. Параллельный регистр исключений не создаётся.

---

## 3. Общие требования к доработке

1. Реализовать в расширении `НП`. Префикс объектов — `нп_`.
2. Не изменять типовую проверку даты запрета при записи документов и справочников.
3. Записывать в типовой РС только ключи настоящего механизма (см. п. 4).
4. Не копировать и не изменять формы ТН на типовом регистре.
5. Интеграцию с 1С:Документооборот 3 выполнять штатными средствами БИД (`ИнтеграцияС1СДокументооборот3*`, `ОбъектыИнтегрированныеС1СДокументооборотом`, `СостоянияСогласованияВДокументообороте`).
6. После набора записей в типовой РС вызывать типовое обновление действующих дат запрета (сброс кэша версии).
7. Привилегированная запись в типовой РС допускается только после серверной проверки списка организаций пользователя (для интерактивных действий) либо в контексте регламентного задания (для автосдвига и сопровождения окна заявки).
8. Факты записи (организация, старая/новая дата, режим: сдвиг / окно заявки / разовая установка) фиксировать в журнале регистрации.

---

## 4. Правила записи в типовой регистр

Настоящий механизм создаёт и изменяет только следующие ключи:

| Поле | Значение |
|---|---|
| `Раздел` | выбранный раздел с типом объекта `СправочникСсылка.Организации` **либо** (если раздел не указан) все такие разделы |
| `Объект` | организация из формы / Excel / заявки / настройки автосдвига |
| `Пользователь` | «для всех пользователей» |
| `ДатаЗапрета` | абсолютная дата (начало дня) |
| `ОписаниеДатыЗапрета` | пусто либо «произвольная дата»; относительные варианты БСП не использовать |

Запрещается:

- изменять строки с конкретным пользователем;
- при пустом разделе заполнять разделы, у которых тип объекта не «Организации» (касса, склады, сценарии, банковские счета);
- затирать чужие относительные даты БСП на ключах, которыми механизм не владеет.

Примечание. Индивидуальная дата пользователя в БСП по-прежнему перекрывает дату «для всех пользователей». Заявка и автосдвиг такие строки не открывают и не сдвигают.

## 6. Требования к форме бухгалтера

### 6.1. Назначение

Предоставить бухгалтеру установку дат по своим организациям без роли на весь регистр `ДатыЗапретаИзменения` и без открытия типовой формы администрирования.

### 6.2. Состав формы обработки `нп_УстановкаДатЗапретаИзменения`

1. Список доступных организаций.
2. Число дней автосдвига N и признак включения автосдвига.
3. Команда загрузки из Excel / табличного документа.
4. Команда применения настроек / разовой даты.
5. Команда создания документа `нп_ЗаявкаНаОткрытиеПериода` с подстановкой выбранных организаций.
6. Протокол ошибок (построчно при загрузке).

Типовая форма `РегистрСведений.ДатыЗапретаИзменения.Форма.ДатыЗапретаИзменения` из обработки не открывается.

### 6.3. Список «своих» организаций

По умолчанию — организации, доступные пользователю по правам чтения справочника `Организации` (при наличии учёта ответственных лиц — организации, по которым пользователь является ответственным). Клиентский отбор не является единственной защитой: сервер повторно проверяет организацию перед записью.

### 6.4. Права

Пользователь с ролью `нп_УстановкаДатЗапретаПоОрганизациям` и **без** типовых ролей `ДобавлениеИзменениеДатЗапретаИзменения` / `ЧтениеДатЗапретаИзменения`:

- имеет доступ к обработке, заявке и настройкам автосдвига;
- не имеет доступа к списку всего типового регистра и типовой форме администрирования;
- не может записать чужую организацию (отказ с сообщением).

## 7. Требования к загрузке из Excel

### 7.1. Общие требования

1. Загрузка выполняется командой обработки `нп_УстановкаДатЗапретаИзменения`.
2. Разбор файла — по приёмам типовой подсистемы «Загрузка данных из файла»: табличный документ, сопоставление колонок, построчный протокол.
3. Регистр `ДатыЗапретаИзменения` в типовой список загружаемых справочников **не** добавляется.

### 7.2. Колонки файла

| № | Колонка | Обязательность | Действие |
|---|---|---|---|
| 1 | Организация (наименование / код / ИНН — по правилам сопоставления) | да | поиск в справочнике `Организации` |
| 2 | N (число дней автосдвига) | нет | при N > 0 — upsert в `нп_НастройкиАвтосдвигаДатЗапрета` |
| 3 | Дата запрета (абсолютная) | нет | разовая запись в типовой РС; **не** включает автосдвиг, если N не задан |
| 4 | Раздел учёта | нет | пусто = все разделы с типом «Организации»; иначе только указанный раздел |

### 7.3. Правила применения строк

1. Неоднозначное или отсутствующее сопоставление организации — строка не записывается, в протоколе ошибка сопоставления.
2. Организация вне доступного бухгалтеру списка — строка не применяется, в протоколе отказ по правам.
3. Корректные строки попадают в таблицу формы и применяются согласно п. 4.
4. Явный раздел должен существовать и иметь тип объекта «Организации»; иначе строка не применяется с ошибкой в протоколе.

## 8. Требования к автосдвигу дат

### 8.1. Настройки

Регистр `нп_НастройкиАвтосдвигаДатЗапрета`:

| Реквизит | Тип / смысл |
|---|---|
| Организация | `СправочникСсылка.Организации` |
| Количество дней N | число > 0 |
| Включено | булево |

Настройки задаются формой бухгалтера и/или колонкой N в Excel. Типовые относительные описания («конец прошлого месяца» и т.п.) не подменяются.

### 8.2. Регламентное задание `нп_СдвигДатЗапретаИзменения`

Для каждой включённой настройки, по которой **нет** действующего окна заявки (п. 9.4):

`ДатаЗапрета` = начало дня текущей даты сеанса − N дней.

Пример: выполнение 18.08, N = 10 → `ДатаЗапрета` = 08.08. На следующий день при тех же условиях граница сдвигается на один день вперёд.

### 8.3. Ограничения задания

1. Изменяются только ключи механизма (п. 4).
2. Персональные строки пользователей не изменяются.
3. Запись выполняется привилегированно и не должна отменяться проверкой даты запрета по самим записям механизма.
4. При наличии живого окна заявки по организации задание **не** записывает `сегодня − N` по ключам этой заявки.
5. После истечения окна при включённом автосдвиге задание восстанавливает `сегодня − N`.

## 9. Требования к заявке на открытие периода

### 9.1. Документ `нп_ЗаявкаНаОткрытиеПериода`

| Реквизит | Обязательность | Описание |
|---|---|---|
| Организации (ТЧ) | да | одна или несколько организаций |
| Срок действия K, дней | да | целое число > 0 |
| Период с | да | начало открываемого периода |
| Период по | да | окончание открываемого периода; `ПериодС` ≤ `ПериодПо` |
| Раздел учёта | нет | элемент ПВХ `РазделыДатЗапретаИзменения`; пусто = все разделы с типом «Организации» |

При незаполненных обязательных полях запись документа отклоняется с указанием незаполненных реквизитов.

На форме заявки выводится пояснение: отсечка БСП откроет **всё после** `ПериодС − 1 день`, а не только выбранный месяц (открытие июля при уже закрытом августе откроет и август до новой отсечки).

### 9.2. Согласование в 1С:Документооборот 3

1. Отправка — `ИнтеграцияС1СДокументооборот3.НачатьОбработку` (или эквивалент штатного API БИД, используемый пилотными документами, в т.ч. контур `нп_КонтрольПроведенияПоДО`).
2. Маршрут настраивается в ДО 3, в ERP не дублируется.
3. Связь объекта — `ОбъектыИнтегрированныеС1СДокументооборотом`.
4. Статус — `СостоянияСогласованияВДокументообороте`. Регламентное задание в веб-сервис ДО не обращается.
5. Если веб-сервис ДО недоступен в момент отправки: заявка не считается согласованной, даты не меняются, пользователю выводится ошибка сервиса.

### 9.3. Запись в регистр только после согласования

Пока состояние не равно `Согласован` (черновик, нет связи с ДО, `НаСогласовании`, отказ), заявка **не** изменяет типовой РС.

### 9.4. Окно действия

День 1 = дата установки состояния `Согласован` (начало дня).

Окно: с даты согласования по `дата согласования + (K − 1)` включительно.

Пример: согласовано 18.08, K = 5 → окно 18.08–22.08 включительно. 23.08 окно истекло.

### 9.5. Значение отсечки на время окна

По ключам заявки (п. 4):

`ДатаЗапрета` = `ПериодС` − 1 день.

Пример: открывается период 01.07–31.07 → в типовой РС записывается 30.06.

Пока окно живо, автосдвиг эти ключи не перезаписывает `сегодня − N`. После истечения окна при включённом автосдвиге восстанавливается `сегодня − N`.

Адресат записи — «для всех пользователей». Персональные строки пользователей заявка не изменяет.

## 10. Алгоритмы

### 10.1. Применение строки формы / Excel

1. Определить организацию и проверить, что она входит в доступный пользователю список. Иначе — отказ.
2. Определить набор разделов: явный раздел либо все разделы с типом объекта «Организации».
3. Если задано N > 0 — записать/обновить `нп_НастройкиАвтосдвигаДатЗапрета` (организация, N, включено).
4. Если задана абсолютная дата — записать ключи типового РС (п. 4) с этой датой. Если N не задан, автосдвиг по этой строке не включать.
5. Обновить действующие даты запрета БСП.
6. Записать событие в журнал регистрации.

### 10.2. Регламентное задание

Для каждой включённой настройки автосдвига:

1. Найти действующие согласованные заявки по организации (окно по п. 9.4 ещё не истекло).
2. Если живое окно есть:
   - убедиться, что по ключам заявки стоит `ПериодС − 1`;
   - `сегодня − N` по этим ключам не записывать.
3. Если живого окна нет:
   - рассчитать `сегодня − N`;
   - записать только ключи механизма по организации настройки.
4. Не изменять персональные строки и разделы иных типов объектов.
5. Обновить действующие даты запрета БСП.
6. Записать результат в журнал регистрации.

### 10.3. Согласование заявки

1. Пользователь записывает документ (проверка п. 9.1). Типовой РС не меняется.
2. Пользователь инициирует обработку в ДО 3. При ошибке сервиса — сообщение, статус «согласован» не ставится.
3. После появления состояния `Согласован`:
   - вычислить окно по п. 9.4;
   - записать в типовой РС `ПериодС − 1` по ключам заявки;
   - обновить действующие даты запрета БСП.
4. Дальнейшее сопровождение окна — регламентным заданием (п. 10.2).

---

## 11. Требования к интерфейсу и сообщениям

1. Форма бухгалтера не содержит команд открытия типового администрирования регистра.
2. Протокол Excel — построчный, с причиной отказа (сопоставление, права, неверный раздел).
3. На форме заявки — предупреждение об односторонней отсечке БСП (п. 9.1).
4. Отказ записи чужой организации — понятное сообщение без частичной записи набора.

| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Автосдвиг без заявки, N = 10, дата сеанса 18.08 | В типовом РС по ключам механизма `ДатаЗапрета` = 08.08; на следующий день — 09.08 |
| 2 | Заявка K = 5 согласована 18.08, период с 01.07 | 18.08–22.08 в РС отсечка 30.06; задание 20.08 не ставит `сегодня − N`; 23.08 при включённом N снова `сегодня − N` |
| 3 | Excel: валидная организация, N, чужая организация, пустой и явный раздел | Свои строки применяются по правилам п. 7; чужая — в протоколе отказ; пустой раздел не трогает кассу/склад/сценарии/банк |
| 4 | Бухгалтер без типовых ролей РС | Обработка открывается; типовая форма регистра недоступна; чужие организации не записываются |
| 5 | По организации есть персональная дата пользователя | Автосдвиг и заявка эту строку не меняют |
| 6 | Заявка записана, но не согласована | Типовой РС этой заявкой не изменён |
| 7 | Сервис ДО недоступен при отправке | Ошибка пользователю; заявка не согласована; даты не изменены |
| 8 | Стиль метаданных | Префикс `нп_`, объекты в подсистеме расширения НП, области модулей по стандартам 1С |

## 13. Порядок внедрения

1. Установить расширение НП. Назначить бухгалтерам роль `нп_УстановкаДатЗапретаПоОрганизациям`. Типовую роль на весь регистр не выдавать.
2. Заполнить `нп_НастройкиАвтосдвигаДатЗапрета` (форма или Excel).
3. Включить регламентное задание сначала в копии, сверить ключи, затем в рабочей базе.
4. В 1С:Документооборот 3 завести вид документа и правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`.
5. Откат: выключить задание и прекратить использование обработки/заявок. Записи типового РС остаются последними абсолютными значениями; при необходимости правит администратор дат запрета.

## 14. Открытые вопросы (значения по умолчанию до уточнения)

| Вопрос | Принято для реализации |
|---|---|
| Как определять «свои» организации | Права чтения справочника `Организации` / ответственные лица. Отдельный РС ответственных в MVP не вводится |
| Раздел «Банк» при пустом разделе заявки/Excel | Не включается (объект — банковский счёт, не организация) |
| Нужно ли проведение заявки | Нет; достаточно записи документа и статуса ДО |
