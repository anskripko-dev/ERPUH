# Техническое задание

**Тема:** автосдвиг дат запрета изменения и заявка на открытие периода

**Конфигурация:** 1С:ERP. Управление холдингом, 3.2.8.25 (режим совместимости 8.3.27)

**Место реализации:** расширение `НП` (префикс `нп_`)

**Дата:** 18.08.2026

---

## 1. Общие сведения

### 1.1. Основание

Настоящее техническое задание подготовлено по требованию бухгалтерии холдинга.

Типовой механизм БСП «Даты запрета изменения» закрывает период: объекты с датой не позднее установленной границы записывать нельзя. Для организаций граница задаётся абсолютной датой. Эту дату приходится регулярно переносить вручную. Отдельной заявки на временное открытие уже закрытого периода с согласованием в 1С:Документооборот 3 в типовой конфигурации нет.

### 1.2. Назначение

Доработка предназначена для автоматического сдвига абсолютной даты запрета («сегодня минус N дней») и для согласованного временного открытия периода по заявке. Типовая проверка периода при записи объектов не изменяется.

### 1.3. Пользователи

| Роль в процессе | Действия |
|---|---|
| Инициатор заявки | создание и отправка документа `нп_ЗаявкаНаОткрытиеПериода` |
| Согласующий в 1С:Документооборот 3 | согласование заявки |
| Администратор дат запрета | заполнение настроек автосдвига, типовой регистр и типовая форма (без изменений) |
| Регламентное задание | ночной пересчёт абсолютных дат и сопровождение срока действия открытого периода |

### 1.4. Вне рамок настоящей доработки

Постоянно:

1. Изменение типовых подписок и модулей проверки даты запрета (`ПередЗаписью`).
2. Новый относительный вариант БСП вида «прошло N дней» в `ОписаниеДатыЗапрета`.
3. Открытие только середины закрытого диапазона (например, открыт только июль при уже закрытом начале августа). Одной датой БСП это невозможно: запрещено всё с датой не позднее `ДатаЗапрета`.
4. Перезапись персональных дат пользователей, а также разделов «Касса», «Складские операции», «Бюджетирование», «Планирование», «Банк» (банковские счета) при пустом разделе.
5. Правки форм расширения ТН и обработки `нп_ОткрытиеДатЗапретаИзменения`.
6. Согласование через подсистему согласования УХ вместо 1С:Документооборот 3.

Отложено (возможен возврат отдельным изменением):

7. Форма бухгалтера без прав на весь типовой регистр и роль `нп_УстановкаДатЗапретаПоОрганизациям`.
8. Массовая загрузка из Excel.

## 2. Характеристика объекта автоматизации

### 2.1. Типовой механизм

Даты запрета хранятся в регистре сведений `ДатыЗапретаИзменения`.

| Измерение / ресурс | Назначение |
|---|---|
| `Раздел` | раздел учёта (ПВХ `РазделыДатЗапретаИзменения`) |
| `Объект` | организация (для разделов с типом объекта «Организации») |
| `Пользователь` | пользователь либо значение «для всех пользователей» |
| `ДатаЗапрета` | граница: запрещено изменение объектов с датой не позднее этой границы |
| `ОписаниеДатыЗапрета` | относительный вариант БСП либо произвольная дата |

Проверка односторонняя. Произвольная абсолютная дата не имеет отсрочки (`КоличествоДнейРазрешения` равно 0).

### 2.2. Принцип настоящей доработки

Эффективная отсечка хранится **только** в типовом регистре. Новые объекты расширения задают, какие абсолютные значения туда записывать и когда. Параллельный регистр исключений не создаётся.

---

## 3. Общие требования к доработке

1. Реализовать в расширении `НП`. Префикс объектов - `нп_`.
2. Не изменять типовую проверку даты запрета при записи документов и справочников.
3. В типовой регистр сведений `ДатыЗапретаИзменения` записывать только записи, указанные в п. 4: раздел учёта, организация, адресат (все пользователи, группа пользователей или пользователь). Прочие записи этого регистра не изменять.
4. Не копировать и не изменять формы ТН на типовом регистре.
5. Интеграцию с 1С:Документооборот 3 выполнять штатными средствами БИД (`ИнтеграцияС1СДокументооборот3`, `ОбъектыИнтегрированныеС1СДокументооборотом`, `СостоянияСогласованияВДокументообороте`).
6. После набора записей в типовой РС вызывать типовое обновление действующих дат запрета (сброс кэша версии).
7. Запись в типовой РС выполняется регламентным заданием и серверной логикой после состояния `Согласован`. Интерактивная запись типового РС из формы бухгалтера в этой очереди не делается.
8. Факты записи (организация, адресат, раздел, старая и новая дата, режим: автосдвиг или заявка) фиксировать в журнале регистрации.

## 4. Правила записи в типовой регистр

Доработка создаёт и изменяет только записи регистра сведений `ДатыЗапретаИзменения` со следующими значениями:

| Измерение / ресурс | Значение |
|---|---|
| `Раздел` | раздел из настройки или заявки. Если не указан - все разделы с типом объекта `СправочникСсылка.Организации` |
| `Объект` | организация из заявки или настройки автосдвига |
| `Пользователь` | как в типовом регистре: «для всех пользователей», группа пользователей или пользователь. Берётся из настройки автосдвига |
| `ДатаЗапрета` | абсолютная дата (начало дня) |
| `ОписаниеДатыЗапрета` | пусто либо «произвольная дата»; относительные варианты БСП не использовать |

Для одной организации допускается несколько настроек с разным N: по адресату и, при необходимости, по разделу учёта.

Запрещается:

- при пустом разделе заполнять разделы, у которых тип объекта не «Организации» (касса, склады, сценарии, банковские счета);
- изменять записи регистра, которых нет в настройках автосдвига (в том числе даты, заданные только в типовой форме);
- изменять записи регистра с относительной датой БСП, которые не были созданы настоящей доработкой.

Примечание. В БСП дата конкретного пользователя перекрывает дату «для всех пользователей». Поэтому индивидуальный сдвиг нужно задавать отдельной настройкой на этого пользователя (или группу), иначе заявка и автосдвиг по «для всех» на него не подействуют.

## 6. Требования к автосдвигу дат

### 6.1. Настройки

Регистр `нп_НастройкиАвтосдвигаДатЗапрета`:

| Реквизит | Тип / смысл |
|---|---|
| Организация | `СправочникСсылка.Организации` |
| Адресат | «для всех пользователей», группа пользователей или пользователь (как измерение `Пользователь` типового регистра) |
| Раздел учёта | элемент ПВХ `РазделыДатЗапретаИзменения`; не обязателен |
| Количество дней N | число больше 0; своё значение для сочетания организация + адресат + раздел |
| Включено | булево |

Пустой адресат означает «для всех пользователей». Пустой раздел означает все разделы с типом «Организации». Если по той же организации и адресату есть и настройка без раздела, и настройка с конкретным разделом, для этого раздела действует настройка с заполненным разделом, для остальных - настройка без раздела.

Настройки задаются формой списка или записи регистра. Типовые относительные описания («конец прошлого месяца» и аналогичные) не подменяются.

### 6.2. Регламентное задание `нп_СдвигДатЗапретаИзменения`

Для каждой включённой настройки, по которой нет действующей заявки на открытие периода по той же организации и тому же разделу (п. 7.4):

`ДатаЗапрета` равна началу дня текущей даты сеанса минус N дней этой настройки.

Пример: выполнение 18.08, заявки нет. По организации для всех пользователей без раздела N равно 10, для раздела «Учет по МСФО» N равно 3, для пользователя Иванова без раздела N равно 5. В типовом регистре: для всех пользователей по обычным разделам `ДатаЗапрета` равна 08.08, по МСФО - 15.08, для Иванова - 13.08. На следующий день границы сдвигаются на один день вперёд.

### 6.3. Ограничения задания

1. Изменяются только записи, указанные в п. 4, по адресату и разделу из настройки.
2. Записи типового регистра, которых нет в настройках автосдвига, не изменяются.
3. Запись выполняется привилегированно и не должна отменяться проверкой даты запрета по самим записям механизма.
4. Если есть согласованная заявка со сроком действия открытого периода, который не истёк, задание не записывает `сегодня минус N` в записи, которые эта заявка покрывает (организация, раздел, адресаты настроек). По остальным разделам той же организации автосдвиг продолжается.
5. После истечения срока действия открытого периода при включённом автосдвиге задание восстанавливает для каждой настройки своё `сегодня минус N`.

## 7. Требования к заявке на открытие периода

### 7.1. Документ `нп_ЗаявкаНаОткрытиеПериода`

| Реквизит | Обязательность | Описание |
|---|---|---|
| Организации (ТЧ) | да | одна или несколько организаций |
| Срок действия открытого периода, дней (K) | да | целое число больше 0 |
| Период с | да | начало открываемого периода учёта |
| Период по | да | окончание открываемого периода; «Период с» не позже «Период по» |
| Раздел учёта | нет | элемент ПВХ `РазделыДатЗапретаИзменения`; пусто - все разделы с типом «Организации» |

При незаполненных обязательных полях запись документа отклоняется с указанием незаполненных реквизитов.

На форме заявки выводится пояснение: отсечка БСП откроет всё после даты «Период с минус 1 день», а не только выбранный месяц (открытие июля при уже закрытом августе откроет и август до новой отсечки).

### 7.2. Согласование в 1С:Документооборот 3

1. Отправка - `ИнтеграцияС1СДокументооборот3.НачатьОбработку` (или эквивалент штатного API БИД, используемый пилотными документами, в том числе контур `нп_КонтрольПроведенияПоДО`).
2. Маршрут настраивается в ДО 3, в ERP не дублируется.
3. Связь объекта - `ОбъектыИнтегрированныеС1СДокументооборотом`.
4. Статус - `СостоянияСогласованияВДокументообороте`. Регламентное задание в веб-сервис ДО не обращается.
5. Если веб-сервис ДО недоступен в момент отправки: заявка не считается согласованной, даты не меняются, пользователю выводится ошибка сервиса.

### 7.3. Запись в регистр только после согласования

Пока состояние не равно `Согласован` (черновик, нет связи с ДО, «На согласовании», отказ), заявка не изменяет типовой РС.

### 7.4. Срок действия открытого периода

Срок действия открытого периода отсчитывается от даты установки состояния `Согласован` (начало дня). День согласования - день 1.

Срок действия открытого периода: с даты согласования по дату «дата согласования плюс (K минус 1)» включительно.

Пример: согласовано 18.08, K равно 5 - срок действия открытого периода с 18.08 по 22.08 включительно. 23.08 срок действия открытого периода истек.

### 7.5. Значение отсечки на срок действия открытого периода

В записи регистра сведений `ДатыЗапретаИзменения` по организациям заявки, разделу заявки (или всем разделам с типом «Организации», если раздел пуст) и адресатам из настроек автосдвига этих организаций (п. 4):

`ДатаЗапрета` равна «Период с» минус 1 день.

Если по организации нет настроек автосдвига, записывается адресат «для всех пользователей».

Пример: открывается период с 01.07 по 31.07 - в типовой РС записывается 30.06.

Пока срок действия открытого периода не истёк, автосдвиг эти записи не перезаписывает значением `сегодня минус N`. После истечения срока действия открытого периода при включённом автосдвиге восстанавливается своё `сегодня минус N` каждой настройки.

Заявка изменяет те же адресаты, что ведутся автосдвигом (все пользователи, группы, пользователи). Строки типового регистра, которых нет в настройках, заявка не изменяет.

## 8. Алгоритмы

### 8.1. Регламентное задание

Для каждой включённой настройки автосдвига:

1. Найти согласованные заявки, срок действия открытого периода которых (п. 7.4) ещё не истёк и которые покрывают организацию и раздел этой настройки.
2. Если такая заявка есть:
   - убедиться, что в записях регистра по заявке (п. 4) стоит «Период с минус 1 день»;
   - `сегодня минус N` в эти записи не записывать.
3. Если действующей заявки по этой настройке нет:
   - рассчитать `сегодня минус N` данной настройки;
   - записать записи по п. 4 для организации, адресата и раздела настройки.
4. Не изменять записи, которых нет в настройках, и разделы иных типов объектов.
5. Обновить действующие даты запрета БСП.
6. Записать результат в журнал регистрации.

### 8.2. Согласование заявки

1. Пользователь записывает документ (проверка п. 7.1). Типовой РС не меняется.
2. Пользователь инициирует обработку в ДО 3. При ошибке сервиса - сообщение, статус «согласован» не ставится.
3. После появления состояния `Согласован`:
   - определить срок действия открытого периода по п. 7.4;
   - записать в типовой РС «Период с минус 1 день» по организациям, разделу и адресатам заявки (п. 7.5);
   - обновить действующие даты запрета БСП.
4. Дальнейшее сопровождение срока действия открытого периода - регламентным заданием (п. 8.1).

## 9. Требования к интерфейсу и сообщениям

1. На форме заявки - предупреждение об односторонней отсечке БСП (п. 7.1).
2. Ошибка сервиса ДО - понятное сообщение; заявка не считается согласованной.

| 2 | Заявка, K равно 5, согласована 18.08, период с 01.07 | С 18.08 по 22.08 в РС отсечка 30.06 по покрытым записям; задание 20.08 не ставит `сегодня минус N` по ним; 23.08 снова своё N каждой настройки |

| 4 | Настройка на пользователя Иванова, N равно 5, и настройка «для всех», N равно 10 | У Иванова граница 13.08, у остальных 08.08 (при дате сеанса 18.08) |
| 5 | Настройка без раздела N равно 10 и настройка на раздел «Учет по МСФО» N равно 3 | По МСФО граница 15.08, по остальным разделам с типом «Организации» - 08.08 |
| 6 | Заявка записана, но не согласована | Типовой РС этой заявкой не изменён |
| 7 | Сервис ДО недоступен при отправке | Ошибка пользователю; заявка не согласована; даты не изменены |
| 8 | Стиль метаданных | Префикс `нп_`, объекты в подсистеме расширения НП, области модулей по стандартам 1С |

## 11. Порядок внедрения

1. Установить расширение НП.
2. Заполнить `нп_НастройкиАвтосдвигаДатЗапрета` (форма регистра).
3. Включить регламентное задание сначала в копии, сверить записи типового регистра, затем в рабочей базе.
4. В 1С:Документооборот 3 завести вид документа и правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`.
5. Откат: выключить задание и прекратить использование заявок. Записи типового РС остаются последними абсолютными значениями; при необходимости правит администратор дат запрета.
