## Context

Нужен массовый отчёт «где используется» по двум справочникам ERP УХ — `Номенклатура` и `Контрагенты`. Типовая форма мест использования БСП работает по одной ссылке. Дополнительные реквизиты уже описаны в метаданных этих справочников (наборы `Справочник_Номенклатура` / `Справочник_Контрагенты`, ТЧ `ДополнительныеРеквизиты`).

Поставка — **внешний отчёт** (`ExternalReports/…`, регистрация в доп. отчётах БСП). Расширение `нп_АнализСсылокСправочников` остаётся как альтернатива постоянной установки. В `uhnp.НП` объекты не дублируем в этой задаче.

## Goals / Non-Goals

**Goals:**
- Внешний отчёт `нп_МестаИспользованияНоменклатурыИКонтрагентов` с `СведенияОВнешнейОбработке` (вид дополнительный отчёт)
- Выбор справочника параметром СКД; отбор СКД включая доп. реквизиты
- Поиск всех ссылок платформенным механизмом; группировка по типу метаданных ссылающегося объекта; количество
- Стандартная форма отчёта БСП (`ОпределитьНастройкиФормы`)

**Non-Goals:**
- Поиск ссылок по произвольным другим справочникам
- Перестроение ссылок / замена ссылок / удаление
- Интерактивный поиск «как в форме МестаИспользования» по одной ссылке
- Сборка `.erf` / `.cfe` в этой среде (нет платформы 1С)

## Decisions

### 1. Внешний отчёт — основная поставка

**Решение:** XML-выгрузка внешнего отчёта в `ExternalReports/нп_МестаИспользованияНоменклатурыИКонтрагентов/`, регистрация через `СведенияОВнешнейОбработке()`: вид `ДополнительныйОтчет`, `ОпределитьНастройкиФормы = Истина`, `БезопасныйРежим = Ложь` (поиск ссылок вызывает привилегированный режим БСП). Назначение разделов: Склад, Продажи, Закупки. Расширение `нп_АнализСсылокСправочников` сохраняется как опциональный контур.

**Альтернативы:** только расширение — требует публикации в ИБ; объект в `нп_КонтрольПроведенияПоДО` — чужой контур.

### 2. СКД: запрос элементов + внешний набор мест использования

**Решение:** набор данных-запрос по выбранному справочнику с блоком `{ХАРАКТЕРИСТИКИ}` для доп. реквизитов; набор данных-объект `МестаИспользования`, заполняемый в `ПриКомпоновкеРезультата`. Связь по `Ссылка` = `ЭлементСправочника`. Вариант: группировки Элемент → Тип значения → Ссылающийся объект; ресурс `КоличествоСсылок`.

Список свойств в `{ХАРАКТЕРИСТИКИ}` не может содержать `РАЗЛИЧНЫЕ` вместе с полем `ТипЗначения` (описание типов — поле неограниченной длины). Уникальность берётся подзапросом `ВЫБРАТЬ РАЗЛИЧНЫЕ Свойство`; `Заголовок` и `ТипЗначения` выбираются во внешнем запросе.

**Альтернативы:** только `НайтиПоСсылкам` без СКД-отбора — нет произвольного отбора по доп. реквизитам; чистый запрос по всем таблицам конфигурации — хрупко и неполно.

### 3. Смена справочника — подмена текста запроса схемы

**Решение:** параметр `ВидСправочника` (строка: `Номенклатура` / `Контрагенты`). В `ПередЗагрузкойНастроекВКомпоновщик` подставляется текст запроса и набор характеристик выбранного справочника, схема подключается через `ОтчетыСервер.ПодключитьСхему`. `ЗагрузитьНастройкиПриИзмененииПараметров` содержит этот параметр, чтобы поля отбора (включая доп. реквизиты) обновились.

**Альтернативы:** два отдельных отчёта — дублирование; два набора в одной схеме без подмены — в списке полей отбора смешиваются характеристики обоих справочников.

### 4. Поиск ссылок — БСП, с запасным вариантом платформы

**Решение:** `ОбщегоНазначения.МестаИспользования` (внутри — `НайтиПоСсылкам`, представления, отметки служебных связей). Если общий модуль недоступен — прямой `НайтиПоСсылкам`. Поиск выполняется по массиву ссылок, полученному компоновкой запроса элементов с пользовательским отбором.

Тип значения в отчёте — `Метаданные.Представление()` (синоним объекта); для сортировки/стабильности дополнительно хранится полное имя метаданных.

### 5. Лимит выборки

**Решение:** параметр `ЛимитЭлементов` (по умолчанию 1000). Если отбор вернул больше — в результат попадают первые N (порядок: наименование, код), в журнал / сообщение пользователю — факт усечения. Снимает риск часового `НайтиПоСсылкам` по всему справочнику.

### 6. Элементы без ссылок

**Решение:** элемент с нулём ссылок остаётся в результате (строка без вложенных ссылок, количество 0). Для этого набор мест использования дополняется строками элементов без найденных ссылок либо связь СКД оставляет «левую» сторону запроса.

## Risks / Trade-offs

- [Производительность `НайтиПоСсылкам`] → лимит элементов, отборы по умолчанию (не группы, не помеченные на удаление), `ФормироватьСразу = Ложь`
- [Неполный состав доп. реквизитов номенклатуры по видам] → в список характеристик входят свойства набора `Справочник_Номенклатура` и наборов `ВидыНоменклатуры.НаборСвойств`; если вид не задан в метаданных набора, часть свойств может не попасть в доступные поля
- [Конфликт UUID при загрузке рядом с `uhnp.НП`] → новые UUID; не подключать дубли объектов в одной ИБ
- [Служебные ссылки (наборы свойств, идентификаторы)] → показываем все, как требует ТЗ; пользователь может отфильтровать тип значения в СКД
- [Нет сборки `.cfe` здесь] → исходники `configurator/` загружаются в конфигуратор на стенде

## Migration Plan

1. Собрать `.erf` из `ExternalReports/нп_МестаИспользованияНоменклатурыИКонтрагентов/` и зарегистрировать в доп. отчётах (или открыть через Файл → Открыть).
2. Проверить формирование по обоим справочникам и отбор по доп. реквизиту.
3. Откат: снять регистрацию внешней обработки.

Опционально: загрузить расширение из `Extensions/нп_АнализСсылокСправочников/configurator`.
