## ADDED Requirements

### Requirement: Report as additional external report
Система SHALL предоставлять тот же отчёт как внешний отчёт (`нп_МестаИспользованияНоменклатурыИКонтрагентов`) с регистрацией в справочнике дополнительных отчётов и обработок (вид «Дополнительный отчет»).

#### Scenario: Register additional report
- **WHEN** пользователь загружает `.erf` в дополнительные отчёты и обработки
- **THEN** появляется команда «Места использования номенклатуры и контрагентов» в назначенных разделах

#### Scenario: Open without registration
- **WHEN** пользователь открывает `.erf` через «Файл — Открыть»
- **THEN** открывается форма отчёта и доступно формирование с отбором и поиском ссылок

### Requirement: Catalog selection
Отчёт SHALL позволять сформировать список элементов справочника **Номенклатура** либо справочника **Контрагенты**. Выбор справочника обязателен; по умолчанию выбран справочник Номенклатура.

#### Scenario: Default catalog is nomenclature
- **WHEN** пользователь открывает отчёт без изменения параметра вида справочника
- **THEN** отбор и выборка выполняются по `Справочник.Номенклатура`

#### Scenario: Switch to counterparties
- **WHEN** пользователь выбирает вид справочника «Контрагенты» и формирует отчёт
- **THEN** отбор и выборка выполняются по `Справочник.Контрагенты`

### Requirement: Arbitrary filter including additional attributes
Отчёт SHALL позволять произвольный отбор элементов выбранного справочника средствами СКД, включая стандартные реквизиты (код, наименование, группа, пометка удаления, признак группы) и дополнительные реквизиты набора свойств справочника.

#### Scenario: Filter by additional attribute
- **WHEN** пользователь задаёт отбор по дополнительному реквизиту номенклатуры или контрагента и формирует отчёт
- **THEN** в результат попадают только элементы, у которых значение этого дополнительного реквизита удовлетворяет отбору

#### Scenario: Filter by name and exclusion of groups
- **WHEN** задан отбор по наименованию и «Это группа = Нет»
- **THEN** в результат не попадают группы и элементы, не удовлетворяющие отбору по наименованию

### Requirement: References grouped by value type
Для каждого элемента, прошедшего отбор, отчёт SHALL выводить все найденные ссылки на этот элемент, сгруппированные по типу значения ссылающегося объекта (представление объекта метаданных), и показывать количество ссылок на уровне элемента и на уровне типа значения.

#### Scenario: Document and catalog references
- **WHEN** на элемент номенклатуры есть ссылки из документов реализации и из справочника характеристик
- **THEN** ссылки выводятся в группах соответствующих типов значения, у каждой группы указано количество ссылок, у элемента — общее количество

#### Scenario: Item without references
- **WHEN** элемент проходит отбор, но ссылок на него нет
- **THEN** элемент присутствует в отчёте с количеством ссылок 0

### Requirement: Reference details
Внутри группы типа значения отчёт SHALL выводить каждую найденную ссылку (ссылающийся объект или ключ записи) так, чтобы пользователь мог открыть расшифровку.

#### Scenario: Drill-down to referencing object
- **WHEN** пользователь открывает расшифровку строки ссылающегося объекта, являющегося ссылкой информационной базы
- **THEN** открывается форма этого объекта

### Requirement: Default filters
По умолчанию отчёт SHALL исключать группы иерархического справочника и элементы, помеченные на удаление. Пользователь может снять эти отборы.

#### Scenario: Default excludes folders and deletion marks
- **WHEN** пользователь формирует отчёт с настройками варианта по умолчанию
- **THEN** в выборку не входят группы (`ЭтоГруппа = Истина`) и элементы с `ПометкаУдаления = Истина`
