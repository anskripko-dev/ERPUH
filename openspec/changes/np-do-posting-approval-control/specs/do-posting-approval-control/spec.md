## ADDED Requirements

### Requirement: Configurable posting control by DO approval
Система SHALL предоставлять в расширении НП (`нп_`) настраиваемый контроль проведения документов по состоянию согласования в 1С:Документооборот. Подключение типа документа MUST выполняться записью настройки **по организации** без обязательной правки модулей объекта документа.

#### Scenario: Setting enables control for document type and organization
- **WHEN** для пары (`Документ.ПеремещениеТоваров`, организация документа) в настройках включён `КонтролироватьПроведение` и включены константы интеграции и согласования через ДО
- **THEN** при попытке провести документ этой организации проведение разрешено только при состоянии согласования `Согласован`

#### Scenario: Setting for another organization does not apply
- **WHEN** настройка контроля есть только для организации А, а документ относится к организации Б
- **THEN** механизм НЕ блокирует проведение документа организации Б по причине согласования в ДО

#### Scenario: Setting disabled
- **WHEN** для пары (тип + организация) контроль выключен или запись настройки отсутствует
- **THEN** механизм НЕ блокирует проведение по причине согласования в ДО

#### Scenario: DO integration switched off
- **WHEN** не используются интеграция с ДО и/или согласование через ДО (константы выключены)
- **THEN** контроль проведения по ДО не применяется

### Requirement: Approval status source of truth
Для решения о разрешении проведения система MUST использовать состояние из связки типовых регистров `ОбъектыИнтегрированныеС1СДокументооборотом` и `СостоянияСогласованияВДокументообороте`. Состояние MUST NOT определяться обязательным веб-вызовом к ДО на каждое проведение. Реквизит объекта документа и доп. реквизиты БСП MUST NOT быть источником истины для этой проверки.

#### Scenario: Approved in register allows posting
- **WHEN** документ связан с объектом ДО и в `СостоянияСогласованияВДокументообороте` состояние = `Согласован`
- **THEN** контроль проведения по ДО не устанавливает отказ

#### Scenario: Not approved blocks posting
- **WHEN** контроль включён и состояние отсутствует, равно `НаСогласовании` или `НеСогласован`, либо связи с ДО нет
- **THEN** проведение отменяется (`Отказ`), пользователю выводится понятное сообщение

#### Scenario: No DO link blocks posting
- **WHEN** контроль включён и связи с ДО нет
- **THEN** проведение запрещено

### Requirement: Server-side check on before write
Проверка MUST выполняться на сервере при записи документа в режиме проведения через единую подписку / общий модуль расширения. Запись без проведения и отмена проведения в MVP MUST NOT блокироваться этим контролем.

#### Scenario: Posting mode triggers check
- **WHEN** выполняется `ПередЗаписью` с `РежимЗаписи = Проведение` для контролируемого типа
- **THEN** выполняется проверка согласования

#### Scenario: Write without posting skips check
- **WHEN** документ записывается без проведения
- **THEN** контроль проведения по ДО не устанавливает отказ

#### Scenario: Data exchange load skips check
- **WHEN** `ОбменДанными.Загрузка = Истина`
- **THEN** контроль не применяется

### Requirement: Bypass role
Система SHALL предоставлять роль обхода контроля (`нп_ОбходКонтроляСогласованияДО`). Пользователь с этой ролью MAY проводить документ в обход проверки согласования ДО.

#### Scenario: Bypass role posts unapproved document
- **WHEN** у пользователя есть роль обхода и документ не согласован в ДО
- **THEN** контроль не устанавливает отказ по причине согласования

### Requirement: Approval status on document form
Для документов с включённым контролем система SHALL отображать на форме документа текущее состояние согласования в ДО, полученное из типового регистра состояний (через связь объектов). Отображение на формах, не проходящих штатную точку модификации конфигурации, не гарантируется; серверный запрет проведения при этом сохраняется.

#### Scenario: Form shows approval state
- **WHEN** пользователь открывает форму документа с включённым контролем и существующей связью с ДО
- **THEN** на форме отображается состояние согласования (например, «На согласовании» / «Согласован» / «Не согласован»)

#### Scenario: Form without DO link
- **WHEN** связи с ДО нет
- **THEN** форма показывает отсутствие согласования / пустое состояние без ошибки

### Requirement: Reusable API
Общий модуль расширения SHALL предоставлять экспортные методы для проверки разрешения проведения и получения состояния согласования по ссылке, пригодные для вызова из подписки, форм и (при необходимости) внешних механизмов.

#### Scenario: API returns consistent decision
- **WHEN** вызывается `РазрешеноПроведениеПоСогласованиюДО` для ссылки документа
- **THEN** результат согласован с правилами, применяемыми в `ПередЗаписью`
