# Контроль проведения по согласованию ДО (расширение НП)

Реализация OpenSpec change `np-do-posting-approval-control`.

Префикс объектов: **`нп_`**.

Служебная копия для переноса (без удаления из `uhnp.НП`):  
`Extensions/нп_КонтрольПроведенияПоДО/`  
- `src/` — EDT  
- `configurator/` — выгрузка конфигуратора (`Configuration.xml`); в конфигуратор грузить эту папку

## Объекты

| Объект | Назначение |
|---|---|
| `РС.нп_НастройкиКонтроляПроведенияПоДО` | Настройки по полному имени метаданных + организации (+ дата начала); форма — выпадающий список документов |
| `РС.нп_РазрешенныеРеквизитыПриСогласованииДО` | Белый список реквизитов; форма — списки документов и реквизитов |
| `РС.нп_ПризнакиПересогласованияДО` | Признак «нужно пересогласование» (`DocumentRef`) |
| `Подписка.нп_КонтрольПроведенияПоДОПередЗаписьюДокумента` | Источник — все `DocumentObject`; ранний выход по настройкам |
| `ОМ.нп_КонтрольПроведенияПоСогласованиюДО` | API и логика |
| `ОМ.нп_КонтрольПроведенияПоСогласованиюДОПовтИсп` | Кэш настроек |
| `Роль.нп_ПроведениеБезСогласованияДО` | Проведение без согласования ДО |
| `Подсистема.нп_КонтрольПроведенияПоДО` | Объединяет объекты доработки |
| `&После` `МодификацияКонфигурацииПереопределяемый.ПриСозданииНаСервере` | Статус на форме |

Источник истины статуса: `ОбъектыИнтегрированныеС1СДокументооборотом` + `СостоянияСогласованияВДокументообороте` (без веб-вызова на проведение).

## Внедрение

1. Опубликовать расширение `НП` (`uhnp.НП`).
2. В панели БИД включить:
   - интеграцию с 1С:Документооборот (2.x и/или 3.x);
   - `ИспользоватьСогласованиеЧерез1СДокументооборот`.
3. Создать правило интеграции ДО для `Документ.ПеремещениеТоваров` и маршрут согласования.
4. Заполнить настройку (один раз):

```bsl
нп_КонтрольПроведенияПоСогласованиюДО.УстановитьНастройкуПоУмолчаниюДляПеремещенияТоваров(Организация, ДатаНачалаДействия);
```

Или вручную в РС `Настройки контроля проведения по ДО`:
- Полное имя: `Документ.ПеремещениеТоваров`
- Организация: нужная организация
- Контролировать: Да
- Дата начала действия: дата внедрения (документы раньше этой даты не контролируются)

Настройка задаётся **отдельно для каждой организации**. При включённом контроле и дате документа ≥ порога проведение возможно только после согласования в ДО. Организация без записи в РС не контролируется.

Существенные изменения в **защищённом окне** (есть связь с ДО и состояние ≠ `НеСогласован`, в т.ч. пока статус из обмена пустой): белый список в `нп_РазрешенныеРеквизитыПриСогласованииДО` (имя реквизита или `ТЧ.Реквизит`). При **проведении** подписка прерывает и перезапускает обработку **ДО 3**, проведение отклоняется до нового `Согласован`. Запись без проведения не блокируется (ставится признак в `нп_ПризнакиПересогласованияДО`). Вопрос на форме не используется.

5. Назначить роль `Обход контроля согласования ДО` узкому кругу (аварийный обход / перепроведение без сдвига даты). Полноправные пользователи обходят контроль автоматически.

## Подключение нового типа документа

1. Добавить строку в РС настроек (полное имя документа из списка + организация + дата начала).
2. При необходимости — белый список реквизитов в РС разрешённых.
3. Настроить правило интеграции в ДО.
4. Опубликовать расширение (заимствовать документ не требуется).

## Проверка в ИБ

- [ ] Перемещение без связи с ДО, дата ≥ порога → проведение запрещено
- [ ] Дата документа раньше `ДатаНачалаДействия` → проведение разрешено без согласования
- [ ] Существенные изменения + проведение → перезапуск ДО 3, проведение отклонено до нового согласования
- [ ] Только разрешённые реквизиты → без перезапуска
- [ ] На согласовании / Не согласован → запрещено
- [ ] Согласован → проведение разрешено
- [ ] Запись без проведения и отмена проведения → не блокируются
- [ ] Роль обхода / полный доступ → проведение разрешено
- [ ] Тип/организация без настройки в РС → не затрагивается
- [ ] На форме отображается поле «Согласование ДО»
