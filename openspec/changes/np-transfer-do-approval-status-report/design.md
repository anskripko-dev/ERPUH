## Context

Уточнённое ТЗ: отчёт **«Согласованные, но не проведенные перемещения»** — контроль документов, успешно согласованных в ДО, но ещё не проведённых.

Данные согласования в ERP (без веб-вызова):

| Поле ТЗ | Источник |
|---|---|
| Статус согласования | `СостоянияСогласованияВДокументообороте.Состояние` |
| Дата согласования | `СостоянияСогласованияВДокументообороте.ДатаУстановки` |
| Согласующий | `СостоянияСогласованияВДокументообороте.Установил` (строка) |
| Связь ERP↔ДО | `ОбъектыИнтегрированныеС1СДокументооборотом` |

Реквизиты документа: `Организация`, `Подразделение`, `СкладОтправитель`, `СкладПолучатель`, `Ответственный`, `Автор`, `Проведен`.

## Goals / Non-Goals

**Goals:**
- Внешний отчёт с назначением контроля согласованных непроведённых перемещений
- Отборы: организация, подразделение, склад, ответственный, период, статус согласования
- Колонки по ТЗ; сортировка по умолчанию: дата, номер
- Вариант по умолчанию: статус = `Согласован`, `Проведен = Ложь`

**Non-Goals:**
- Веб-вызовы в ДО 3 (этап маршрута, текущий исполнитель)
- Колонка «требуется пересогласование»
- Универсальный отчёт по всем типам из настроек контроля
- Автопроведение из отчёта

## Decisions

### 1. Назначение и имя

**Решение:** представление отчёта и команды — «Согласованные, но не проведенные перемещения»; техническое имя объекта `нп_СостояниеСогласованияДОПеремещений` сохраняется (уже в репозитории/поставке).

### 2. Условия выборки по умолчанию — в настройках варианта, не жёстко в WHERE

**Решение:** в варианте «Основной» включены отборы `СостояниеСогласования = Согласован` и `Проведен = Ложь`. Пользователь может изменить статус (отбор по статусу из ТЗ) и при необходимости снять отбор по проведению.

**Почему:** ТЗ одновременно фиксирует целевую выборку и требует отбор по статусу.

### 3. Склад — два поля + два отбора

**Решение:** колонки и пользовательские отборы по `СкладОтправитель` и `СкладПолучатель` (ТЗ «Складу»).

### 4. Согласующий и дата — атрибуты РС состояний

**Решение:** `Установил` → «Согласующий»; `ДатаУстановки` → «Дата согласования». Без обращения к ДО.

### 5. Без РС расширения

**Решение:** JOIN к `нп_ПризнакиПересогласованияДО` убрать — отчёт собирается на типовых объектах.

### 6. Период и сортировка

**Решение:** параметр `Период` (стандартный период) → `НачалоПериода`/`КонецПериода` по дате документа; порядок варианта: `Дата`, `Номер`.

## Risks / Trade-offs

- [Пустые `Установил`/`ДатаУстановки` при неполном обмене] → колонки пустые; статус при этом может быть заполнен
- [Несколько связей объекта с ДО] → возможны дубли строк (как у LEFT JOIN по связи)
