## Context

Контур согласования перемещений уже внедрён:

- расширение `Extensions/нп_КонтрольПроведенияПоДО/` запрещает проведение до состояния `Согласован` в ДО;
- источник истины статуса — типовые РС БИД (без веб-вызова):
  - `ОбъектыИнтегрированныеС1СДокументооборотом` (связь ERP ↔ ID объекта ДО);
  - `СостоянияСогласованияВДокументообороте` (состояние по ID);
- на форме документа статус выводится по API `нп_КонтрольПроведенияПоСогласованиюДО.СостояниеСогласованияДО`;
- `Статус` перемещения — логистика (`Отгружено` / `Принято`), не согласование;
- признак перезапуска маршрута — `нп_ПризнакиПересогласованияДО.ТребуетсяПересогласование`.

Нужен внешний отчёт для мониторинга очереди согласования по списку перемещений.

**Ограничения:** исходники в `C:\Projects\ERPUH`; код конфигурации — `C:\EDTProjects\uh_np`; стандарты — `Instructions/стандарты-разработки-1с.md`, СКД — `Instructions/скд-стандарты-разработки-отчетов.md`, внешние объекты — `Instructions/внешние-обработки.md`. Эталон БСП: `Reports/_ДемоОтчетПоСчетамНаОплатуГлобальный` (SSL).

## Goals / Non-Goals

**Goals:**
- Внешний отчёт СКД со списком перемещений и состоянием согласования в ДО
- Регистрация через «Дополнительные отчёты и обработки» (вид `ДополнительныйОтчет`)
- Отборы по периоду, организации, складам, проведённости, состоянию согласования / связи с ДО
- Понятные представления: «Нет связи с Документооборотом», «Связан с ДО, состояние не задано», значения перечисления
- Колонка «Требуется пересогласование» при наличии РС расширения

**Non-Goals:**
- Изменение логики контроля проведения / пересогласования
- Веб-вызовы в ДО 3 (текущий исполнитель, история маршрута) — вне MVP
- Универсальный отчёт по всем типам из настроек контроля (только `ПеремещениеТоваров`)
- Встраивание отчёта в расширение как объект метаданных (поставка — внешний `.erf`)
- Автопроведение / массовый запуск согласования из отчёта

## Decisions

### 1. Внешний отчёт (.erf), не объект расширения

**Решение:** каталог `ExternalReports/нп_СостояниеСогласованияДОПеремещений/`, модуль объекта с `СведенияОВнешнейОбработке()` (`Вид = ДополнительныйОтчет`), команда `ТипКомандыОткрытиеФормы`, `ОпределитьНастройкиФормы = Истина`. Сборка в `.erf`, регистрация в справочнике доп. отчётов.

**Почему:** заказчик просит внешний отчёт; обновляется независимо от расширения контроля; тот же контур поставки, что у внешних ПФ.

**Альтернатива отклонена:** отчёт внутри `нп_КонтрольПроведенияПоДО` — проще ссылаться на РС расширения, но не соответствует формату «внешний».

### 2. Данные — запрос СКД к типовым регистрам (как в API контроля)

**Решение:** набор данных «Запрос»: `Документ.ПеремещениеТоваров` LEFT JOIN связь с ДО LEFT JOIN состояния. Логика представлений состояния — та же, что в `СостояниеСогласованияДО` (нет строки связи → «Нет связи…»; есть связь, пустое состояние → «Связан с ДО, состояние не задано»; иначе — представление перечисления).

Сортировку и итоги не закладывать в текст запроса — через настройки СКД.

**Почему:** один пакетный запрос вместо вызова API построчно; не зависит от доступности веб-сервиса ДО; согласовано с уже принятым источником истины контроля.

**Альтернатива отклонена:** вызов `нп_КонтрольПроведенияПоСогласованиюДО.СостояниеСогласованияДО` в `ПриКомпоновкеРезультата` — медленнее и жёсткая зависимость от расширения при формировании списка.

### 3. Вычисляемое поле представления состояния

**Решение:** в СКД поле `СостояниеСогласованияПредставление` (выражение / вычисляемое поле) по правилам:

| ЕстьСвязьСДО | Состояние | Представление |
|---|---|---|
| Ложь | — | Нет связи с Документооборотом |
| Истина | пусто | Связан с ДО, состояние не задано |
| Истина | значение перечисления | Строка(Состояние) |

Отдельное поле `СостояниеСогласования` (ссылка перечисления / NULL) — для отбора «по состоянию»; отдельное булево `ЕстьСвязьСДО`.

**Почему:** удобный UX в таблице + точные отборы без парсинга строк.

### 4. Пересогласование — LEFT JOIN к РС расширения

**Решение:** LEFT JOIN `РегистрСведений.нп_ПризнакиПересогласованияДО` по документу; ресурс `ТребуетсяПересогласование` (NULL → Ложь в выражении СКД). В README зафиксировать: отчёт рассчитан на ИБ с установленным расширением контроля; при отсутствии РС сборка/открытие схемы потребует убрать JOIN (или поставлять вариант без колонки).

**Почему:** колонка полезна для операторов контроля; регистр уже есть в контуре НП.

**Альтернатива:** не показывать пересогласование в MVP — отклонена как слишком урезанный мониторинг при уже готовом РС.

### 5. Состав колонок (вариант по умолчанию)

**Решение:** таблица (группировка — детальные записи):

- Ссылка, Дата, Номер
- Организация
- СкладОтправитель, СкладПолучатель
- Проведен, ПометкаУдаления
- Статус (логистика документа — справочно)
- ЕстьСвязьСДО
- СостояниеСогласования / СостояниеСогласованияПредставление
- ТребуетсяПересогласование

Параметры: `НачалоПериода`, `КонецПериода` (обязательные в настройках варианта). Пользовательские отборы СКД по организации, складам, проведённости, состоянию, связи с ДО, пересогласованию.

**Почему:** минимальный набор для контроля очереди согласования без перегруза ТЧ товаров.

### 6. Безопасный режим и права

**Решение:** `БезопасныйРежим = Истина` (только чтение); права — стандартные RLS/права на `ПеремещениеТоваров` и чтение регистров ДО. Privileged mode в отчёте не использовать.

**Почему:** отчёт не пишет данные и не вызывает защищённые API записи.

### 7. Расширяемость на другие типы документов

**Решение:** в MVP жёстко `Документ.ПеремещениеТоваров`. В design зафиксировать путь эволюции: параметр/настройка списка полных имён из `нп_НастройкиКонтроляПроведенияПоДО` + объединение запросов — отдельная change.

**Почему:** пилот контроля — перемещения; универсализация усложняет СКД без подтверждённой потребности.

## Risks / Trade-offs

- [Рассинхрон регистра и ДО] → отчёт показывает то же, что контроль проведения; мониторинг обмена БИД остаётся отдельной задачей
- [Зависимость от РС расширения для колонки пересогласования] → README + опциональность JOIN; ядро статуса ДО работает на типовых РС
- [Большие периоды] → обязательный отбор по дате; не грузить ТЧ товаров
- [Внешний отчёт не видит метаданные расширения в конфигураторе при сборке] → собирать `.erf` в ИБ, где расширение уже загружено, либо временно упростить схему до типовых объектов

## Migration Plan

1. Реализовать исходники в `ExternalReports/нп_СостояниеСогласованияДОПеремещений/`
2. Собрать `.erf` в конфигураторе (ИБ с расширением контроля)
3. Зарегистрировать в «Дополнительные отчёты и обработки», разместить в нужном разделе (например, склад / администрирование НП)
4. Проверить на выборке перемещений с разными состояниями ДО

Rollback: снять регистрацию доп. отчёта; исходники остаются в репозитории.
