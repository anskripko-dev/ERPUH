## ADDED Requirements

### Requirement: Report in DO control extension
Система SHALL предоставлять отчёт «Согласованные, но не проведенные перемещения» как объект расширения `нп_КонтрольПроведенияПоДО` (`Отчет.нп_СогласованныеНеПроведенныеПеремещения`), доступный из подсистемы расширения.

#### Scenario: Report available from extension subsystem
- **WHEN** расширение опубликовано и пользователь открывает подсистему контроля проведения по ДО
- **THEN** доступна команда отчёта «Согласованные, но не проведенные перемещения»

#### Scenario: Default selection is approved and not posted
- **WHEN** пользователь формирует отчёт с настройками варианта по умолчанию
- **THEN** в результат попадают только перемещения со состоянием `Согласован` и `Проведен = Ложь`

### Requirement: Output columns
Отчёт SHALL выводить: дату и номер документа, организацию, склад-отправитель, склад-получатель, ответственного, статус согласования, дату согласования, согласующего, признак проведения, пользователя-автора документа.

Дата согласования и согласующий — из `СостоянияСогласованияВДокументообороте.ДатаУстановки` и `.Установил`.

#### Scenario: Row for approved unposted transfer
- **WHEN** перемещение согласовано в ДО, не проведено, у записи состояния заполнены дата установки и установивший
- **THEN** строка содержит эти значения вместе с реквизитами документа и автором

### Requirement: Filters
Отчёт SHALL позволять отбор по организации, подразделению, складу-отправителю, складу-получателю, ответственному, периоду дат документа и статусу согласования.

#### Scenario: Filter by organization and period
- **WHEN** заданы период и организация
- **THEN** в результат попадают только перемещения выбранной организации с датой в периоде

### Requirement: Default sort
По умолчанию результат SHALL упорядочиваться по дате документа, затем по номеру.

#### Scenario: Default order
- **WHEN** формируется вариант по умолчанию без изменения порядка
- **THEN** строки идут по возрастанию даты и номера
