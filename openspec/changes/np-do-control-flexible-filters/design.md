## Context

Контроль ДО уже есть (тип + орг + дата + статус ДО). Evh_ даёт готовый паттерн: СКД-отбор + участники через `СоставыГруппПользователей`.

## Decisions

1. **Вариант A:** одна запись РС на тип+организацию; оба отбора — ресурсы этой записи.
2. **`ОтборПоРеквизитам`:** `ХранилищеЗначения` с `НастройкиКомпоновкиДанных`; пустой/без активных элементов = все документы.
3. **`УчастникиКонтроля`:** `ХранилищеЗначения` с таблицей/массивом `{Участник, ВидСтроки}`; пусто = все пользователи; правило Включая → затем Исключая (как evh_).
4. **Обходчик** в `нп_КонтрольПроведенияПоСогласованиюДОКлиентСервер` (порт `ОтборВыполняется`), без ссылки на evh_.
5. **Порядок:** настройка найдена → дата → отбор реквизитов → отбор пользователей → обход/полноправие → статус ДО.
6. **Полноправные + константа:** отбор по пользователям применяется; константа только отключает авто-обход полноправия.

## Risks

- Неполная семантика иерархических видов сравнения СКД (как в evh_).
- При смене типа документа на форме отбор может стать невалидным — сбрасывать/переинициализировать компоновщик.
