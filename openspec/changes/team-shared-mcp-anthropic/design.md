## Context

Сейчас в `ERPUH` один MCP: `1c-syntax-checker-mcp` на `http://localhost:8002/mcp`. Это удобно одному разработчику и непригодно команде. Код УХ живёт вне git (`C:\EDTProjects\uh_np`), планирование и правила агента — в этом репозитории. Клиент команды — **Cursor + Anthropic (Claude)**. Конкретная EDT не выбрана, поэтому контур не должен начинаться с EDT-плагина.

См. `proposal.md` (зачем) и specs `shared-mcp-gateway`, `mcp-work-profiles`, `anthropic-agent-workspace` (контракт поведения).

## Goals / Non-Goals

**Goals:**

- Один LAN-хост Streamable HTTP, к которому подключаются все Cursor
- Четыре профиля с разным allowlist инструментов
- Claude в Cursor как единственный обязательный агент
- Контекст кода из файловой выгрузки `uhnp` / расширений, пока EDT нет
- Прод вне MCP; секреты вне git

**Non-Goals:**

- Выбор, закупка и установка конкретной EDT
- Обязательный EDT-MCP / CodePilot1C в первой поставке
- Подключение продуктивной ИБ «хотя бы read-only»
- Замена OpenSpec-процесса и правил BSL MCP-инструментами
- Обязательный Docker-комбайн (например onec-mcp-universal) как единственная реализация — это кандидат, не контракт

## Decisions

### 1. Клиент — Cursor, модель — Anthropic

**Решение:** командный агент = Claude в Cursor. HTTP MCP в проектном `.cursor/mcp.json` (`url`), как уже сделано для syntax-checker.

**Почему:** репозиторий уже заточен под Cursor (rules, skills, commands). Claude хорошо следует правилам и вызывает MCP. Streamable HTTP одинаково живёт в Cursor и позже в Claude Code, если понадобится.

**Отклонено:** Claude Desktop + локальный stdio как основной путь — не шарится по сети и дублирует рабочие места. Обязательный Claude Code — ломает текущий процесс `/opsx-*`.

### 2. Транспорт — Streamable HTTP на LAN, не stdio

**Решение:** шлюз слушает `http://<srv-mcp.lan>:<port>/mcp/...`. Перед ним reverse proxy с токеном (заголовок или Basic). В git — URL и имена серверов; токен — в user-level MCP Cursor или env рабочей станции.

**Почему:** stdio живёт внутри одного процесса Cursor. HTTP — единственный способ «несколько людей — один контур». Текущий syntax-checker уже HTTP.

**Отклонено:** по копии MCP на каждом ПК — быстро разъедется версиями и базами.

### 3. Сначала четыре URL профилей, не один «комбайн»

**Решение:** в `.cursor/mcp.json` четыре сервера (`1c-dev`, `1c-analytics`, `1c-test`, `1c-docs`) или меньшее подмножество на старте. Схлопывание в один gateway с per-session routing — фаза 2, если админка зоопарка станет болью.

**Почему:** Claude агрессивно берёт инструменты; 40+ tools в одном списке ухудшают выбор. Профили = и безопасность, и качество агента. Пока EDT нет, `dev` и `docs` можно поднять без живой 1С.

**Отклонено:** один MCP со всеми tools и надеждой, что модель «сама не будет проводить документы».

### 4. EDT — опциональный адаптер после выбора продукта

**Решение:** канонический источник кода для агента — файловая выгрузка (EDT `src/` или `DumpConfigToFiles`). Индекс/поиск и syntax-checker работают по файлам. Когда EDT выберут — можно добавить EDT-MCP как пятое подключение, не меняя профили.

**Почему:** EDT-MCP и CodePilot1C привязаны к конкретной IDE и JDK. Выбор EDT ещё впереди; блокировать команду на этом нельзя.

**Отклонено:** ждать EDT, чтобы «правильно» подключить агента.

### 5. Живые данные — только копии, разные ИБ для analytics и test

**Решение:**

| Профиль | Бэкенд |
|---|---|
| `dev` | выгрузка + BSL checker + справка платформы |
| `analytics` | HTTP-сервис на **аналитической копии** УХ, read-only (метаданные, запрос, журнал) |
| `test` | отдельная тестовая ИБ + runner |
| `docs` | метаданные выгрузки + `openspec/` + `.cursor/rules/` + `Instructions` |

Прод не регистрируется. `execute_code` / проведение — не в `analytics` и `docs`. Если понадобится песочница с записью — отдельный профиль, не смешивать с аналитикой.

**Почему:** иначе агент с широкими tools становится точкой изменения учёта. Разделение ИБ не даёт аналитику сломать прогон тестов.

### 6. Что поднимать по фазам (стек-кандидаты, не вендор-лок)

**Фаза A (без 1С-кластера):** вынести текущий syntax-checker на `srv-mcp`; отдать `docs` через файлы репозитория и выгрузку; поправить `.cursor/mcp.json` и `AGENTS.md`.

**Фаза B:** HTTP-сервис на копии УХ (обработка/расширение MCP toolkit или свой `hs/mcp`) — профиль `analytics`.

**Фаза C:** тестовая ИБ + runner (YaXUnit / синтаксическая проверка).

**Фаза D (после выбора EDT):** опционально EDT-MCP.

Каталог ориентиров: [Untru/1c-mcp](https://github.com/Untru/1c-mcp). Шлюз-комбайн [onec-mcp-universal](https://github.com/voregnev/onec-mcp-universal) допустим на фазе D/B, если команда хочет один порт и dashboard — это реализация, не требование spec.

### 7. Слой политики остаётся в git, не в MCP

**Решение:** MCP даёт факты (метаданные, диагностика, запросы). Как писать BSL, куда класть кастом (`нп_`/`тн_`), процесс propose → apply — `.cursor/rules/`, `openspec/`, `AGENTS.md`.

**Почему:** новый чат Claude не помнит прошлые сессии; правила в репозитории — общий контракт для всех пользователей сети.

## Risks / Trade-offs

- [Открытый MCP в LAN] → любой в подсети читает метаданные и, при ошибке, данные копии. Mitigation: reverse proxy + токен, ACL по IP, не публиковать в интернет
- [Слишком много tools у Claude] → лишние вызовы и риск «провести документ». Mitigation: профили и allowlist
- [Выгрузка устарела относительно ИБ] → агент врёт в коде и инструкциях. Mitigation: расписание обновления дампа после выкладки `uhnp`/расширений
- [Одна копия для аналитики и тестов] → порча тестовых данных. Mitigation: разные ИБ с фазы C
- [ПДн в аналитической копии] → утечка через промпт. Mitigation: обезличивание копии или маскировка на шлюзе; `docs` не опирается на живые документы
- [EDT выберут несовместимую с выбранным плагином] → не ломает контур, если файловый путь канонический
- [Токен в проектном mcp.json] → утечка через git. Mitigation: только user-level / env
- [Cursor usage vs прямые ключи Anthropic] → разные квоты. Mitigation: командная подписка Cursor; не класть API keys в репозиторий

## Migration Plan

1. Зафиксировать hostname `srv-mcp` и сегмент LAN (документом в change, не секретами)
2. Перенести `1c-syntax-checker-mcp` с localhost на шлюз; включить auth
3. Обновить `.cursor/mcp.json` плейсхолдером LAN URL; описать, куда класть токен
4. Обновить `AGENTS.md` / правило: агент = Claude, EDT не обязателен, прод вне MCP
5. Выложить read-only HTTP к аналитической копии → профиль `analytics`
6. Выделить тестовую ИБ → профиль `test`
7. После выбора EDT — отдельный change на EDT-MCP, без ломки HTTP-профилей
8. Откат: вернуть `mcp.json` на localhost; выключить публикацию шлюза — рабочие места деградируют к одиночному режиму

## Open Questions

- Имя хоста и кто администрирует `srv-mcp` (Windows-служба vs Linux Docker) — не меняет spec, только runbook
- Командная подписка Cursor или корпоративные ключи Anthropic — биллинг, не архитектура
- Конкретный пакет HTTP-сервиса 1С (toolkit / своё расширение) — выбирается на фазе B по удобству установки в УХ 3.2.8.25
