## Purpose

Разделяет командный MCP на роли разработки, аналитики, тестирования и инструкций, чтобы у каждой роли был только нужный набор инструментов.

## ADDED Requirements

### Requirement: Four named profiles
Система SHALL публиковать четыре профиля MCP: `dev`, `analytics`, `test`, `docs`. Клиент MUST подключать только профили, назначенные роли пользователя.

#### Scenario: Developer gets the dev profile
- **WHEN** разработчику выдают доступ к командному MCP
- **THEN** ему доступен профиль `dev` (и при необходимости другие явно назначенные профили)

#### Scenario: Analyst does not get write or execute tools
- **WHEN** аналитик подключён только к профилю `analytics`
- **THEN** ему недоступны проведение документов, произвольное выполнение BSL и запись модулей конфигурации

### Requirement: Dev profile capabilities
Профиль `dev` SHALL давать доступ к диагностике BSL, справке платформы и чтению кода/метаданных из файловой выгрузки конфигурации (`uhnp`, `uhnp.НП`, `uhnp.ТН`). Он MUST NOT требовать выбранной EDT для этих операций.

#### Scenario: Syntax check without EDT
- **WHEN** разработчик просит агента проверить модуль расширения НП, а EDT ещё не выбран или не запущен
- **THEN** профиль `dev` позволяет выполнить синтаксическую/статическую проверку через MCP или файловый контекст выгрузки

#### Scenario: Metadata from dump
- **WHEN** агент ищет реквизит или модуль объекта УХ
- **THEN** поиск идёт по выгрузке конфигурации, а не только через плагин конкретной EDT

### Requirement: Analytics profile is read-mostly on a copy
Профиль `analytics` SHALL позволять читать метаданные, выполнять запросы и смотреть журнал на **копии** ИБ. Он MUST NOT проводить документы, записывать объекты учёта и выполнять произвольный BSL.

#### Scenario: Query on copy succeeds
- **WHEN** аналитик через агента запрашивает выборку по тестовой/аналитической копии
- **THEN** инструмент запроса выполняется на этой копии

#### Scenario: Posting is rejected
- **WHEN** аналитик просит провести документ через MCP
- **THEN** профиль `analytics` не предоставляет такой инструмент (или шлюз отказывает)

### Requirement: Test profile uses a dedicated infobase
Профиль `test` SHALL запускать проверки и тесты (синтаксис конфигурации, YaXUnit или эквивалент) только на выделенной тестовой ИБ. Эта ИБ MUST NOT быть той же, что основная аналитическая копия, если на ней одновременно идут произвольные запросы аналитиков.

#### Scenario: Tests run on the test infobase
- **WHEN** тестировщик просит агента прогнать тесты
- **THEN** запуск идёт в тестовой ИБ, а не в продуктивной и не в произвольной базе разработчика

### Requirement: Docs profile uses metadata and project rules
Профиль `docs` SHALL давать чтение метаданных (синонимы, реквизиты, формы), стандартов из репозитория/`Instructions` и OpenSpec. Он MUST NOT читать произвольные учётные документы и суммы из живой базы как источник для инструкции, если это не явно разрешённая обезличенная копия.

#### Scenario: Instruction from metadata and standards
- **WHEN** методист просит написать инструкцию по документу конфигурации
- **THEN** агент опирается на метаданные, правила репозитория и OpenSpec, а не на продуктивные проводки

#### Scenario: Live personal data is not the docs source
- **WHEN** в копии есть персональные или учётные данные
- **THEN** профиль `docs` не использует их как обязательный источник текста инструкции
