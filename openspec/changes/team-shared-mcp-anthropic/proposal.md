## Why

Сейчас MCP для 1С привязан к `localhost` одного разработчика (`.cursor/mcp.json` → `http://localhost:8002/mcp`). Несколько пользователей в одной сети не могут одинаково пользоваться агентом для разработки, аналитики, тестов и инструкций. Нужно общее LAN-подключение под **Anthropic (Claude) в Cursor**, не зависящее от ещё не выбранного EDT.

## What Changes

- Общий HTTP MCP-шлюз в локальной сети вместо персональных `stdio`/`localhost` серверов
- Четыре профиля доступа: разработка, аналитика, тестирование, инструкции — с разным набором инструментов
- Клиенты команды: Cursor + модель Anthropic (Claude). Секреты не в git
- Контекст кода и метаданных — из файловой выгрузки конфигурации / git, **без жёсткой привязки к конкретной EDT**
- Запрет продакшена в MCP; аналитика и тесты — только на копиях ИБ
- Правила агента и шаблон `.cursor/mcp.json` в репозитории `ERPUH`, чтобы новый сотрудник подключался без ручной сборки зоопарка серверов

## Capabilities

### New Capabilities

- `shared-mcp-gateway`: единый Streamable HTTP шлюз в LAN с авторизацией, изоляцией сессий и без доступа к продуктивной ИБ
- `mcp-work-profiles`: профили `dev` / `analytics` / `test` / `docs` с явным allowlist инструментов под роли
- `anthropic-agent-workspace`: рабочее место Claude в Cursor (проектный MCP, правила, скиллы) без зависимости от конкретной EDT

### Modified Capabilities

- (нет — в `openspec/specs/` ещё нет зафиксированных capabilities по MCP)

## Impact

- Репозиторий `ERPUH`: `.cursor/mcp.json`, `.cursor/rules/`, `AGENTS.md`, документация подключения
- LAN-хост `srv-mcp` (вне этого git): шлюз, reverse proxy, токены
- Тестовая / копия ИБ УХ (не прод): HTTP-сервис метаданных и запросов, отдельная ИБ для тестов
- Выгрузка конфигурации `uhnp` / `uhnp.НП` / `uhnp.ТН` как источник кода для агента
- Не затрагивает: выбор и закупку EDT, правки типовой УХ, продуктивный кластер 1С
