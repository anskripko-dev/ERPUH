# Сценарии тестирования дат запрета (целевая база)

Рабочая настройка, от которой считаются все шаги ниже.

| Адресат | Объект | Раздел | N | Смысл |
|---|---|---|---|---|
| Для всех пользователей (пусто) | пусто | пусто | **1** | всем можно править **только сегодня** |
| Группа пользователей складов | пусто | пусто | **5** | кладовщикам — последние 5 календарных дней, включая сегодня |
| Группа «Бухгалтеры» | пусто | пусто | **30** | бухгалтерам — последние 30 календарных дней, включая сегодня |

Пустые объект и раздел — **общая дата адресата**: одна запись типового РС на все разделы и объекты, пока нет более точной записи *у того же адресата*.

Типовой поиск БСП выбирает адресата целиком: конкретный пользователь → группа (если пользователь в нескольких группах — по полю `Комментарий` записи, по убыванию) → «для всех». Наборы разных адресатов **не смешиваются**. Поэтому:

- бухгалтер из группы «Бухгалтеры» живёт по N=30, а не по N=1;
- кладовщик из группы складов — по N=5, а не по N=1;
- менеджер продаж, который не входит в эти группы, — по N=1.

## Норматив N и даты на день теста

N — число последних календарных дней **включая сегодня**. В типовой РС пишется начало дня границы: `сегодня − N`. Документ **в день границы править нельзя**, доступно со следующего дня.

Ниже **D = 01.09.2026** (вторник, III квартал). Если день теста другой — сдвиньте все даты на разницу дней.

| Адресат | N | Запись в типовом РС | Можно править документы с даты |
|---|---|---|---|
| Для всех | 1 | 31.08.2026 | 01.09.2026 (только сегодня) |
| Склады (группа) | 5 | 27.08.2026 | 28.08.2026 |
| Бухгалтеры | 30 | 02.08.2026 | 03.08.2026 |

Заявка **не открывает интервал «с … по …»**. Типовой механизм знает одну границу: отсечка = «Период с» минус 1 день. Всё **после** отсечки становится доступно, в том числе более поздние месяцы. Это написано на форме заявки.

Срок K: день согласования — первый день. Окончание = дата согласования + K − 1 (включительно). Задание возвращает границу, когда дата сеанса **строго больше** окончания (`ДатаОкончанияДействия < сегодня`). Фактический возврат — ночным заданием **на следующий день после последнего дня K** (или ручным запуском в этот день).

| Согласовано | K | Окончание (вкл.) | Задание ещё держит отсечку | Задание возвращает границу |
|---|---|---|---|---|
| 01.09.2026 | 1 | 01.09.2026 | 01.09 23:00 | 02.09 |
| 01.09.2026 | 3 | 03.09.2026 | 01.09, 02.09, 03.09 23:00 | 04.09 |

## 0. Подготовка копии

Исполнитель: администратор ИБ, полные права.

1. Расширение `нп_ДатыЗапретаИзменения` загружено, конфигурация БД расширения обновлена, сеанс перезапущен. Рядом с НП, не внутрь НП.
2. Включены ФО дат запрета **по пользователям**, **по разделам**, **по объектам** — иначе записи с заполненным адресатом/разделом/объектом не применяются.
3. Есть тестовые пользователи (имена любые, роли как в жизни):
   - `Админ` — полные права;
   - `Бухгалтер` — в группе пользователей «Бухгалтеры», роль `нп_БазовыеПраваДатЗапрета` + права отправки в ДО;
   - `Кладовщик` — в группе складов (одна или несколько групп, на каждую будет своя настройка N=5);
   - `МенеджерПродаж` — **не** в группах бухгалтеров и складов, та же роль заявки;
   - согласующий в ДО 3.
4. Выбрана одна организация `ОргА`, по которой есть документы продаж / бухгалтерии (или их можно создать).
5. В ДО 3: вид документа и правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`, печатная форма «Заявка на открытие периода», перенос присоединенных файлов ИС. Реквизиты и ТЧ заявки в документ ДО **не** маппить.
6. Снять снимок типового РС `ДатыЗапретаИзменения` **до** первого запуска задания (особенно общие даты адресатов с пустыми разделом и объектом).
7. Константу получателей уведомлений можно оставить пустой: ошибки задания всё равно пишутся в журнал `нп_СдвигДатЗапретаИзменения`.

### 0.1. Завести настройки автоустановки

Полные права → подсистема «Даты запрета изменения (НП)» → регистр настроек. Три строки, все **Включено**:

| № | Пользователь | Раздел | Объект | N |
|---|---|---|---|---|
| 1 | (пусто = для всех) | (пусто) | (пусто) | 1 |
| 2 | группа складов | (пусто) | (пусто) | 5 |
| 3 | группа «Бухгалтеры» | (пусто) | (пусто) | 30 |

Если групп складов несколько — строка N=5 на каждую группу.

Ручной запуск задания `нп_СдвигДатЗапретаИзменения` (не ждать 23:00).

**Ожидание в типовом РС:**

- одна запись: пользователь = «Для всех пользователей», раздел пуст, объект пуст, дата **31.08.2026**, комментарий `нп_авто`;
- по одной записи на каждую группу складов: дата **27.08.2026**, комментарий `нп_авто|00005`;
- запись группы «Бухгалтеры»: дата **02.08.2026**, комментарий `нп_авто|00030`.

Повторный запуск в тот же день: даты те же, дублей нет.

## 1. Автоустановка без заявок

### 1.1. Менеджер продаж (N=1)

Под `МенеджерПродаж`:

| Действие | Ожидание |
|---|---|
| Записать документ с датой **01.09.2026** (сегодня) | записывается |
| Записать / изменить документ с датой **31.08.2026** | типовой запрет БСП, текст не менялся |
| Записать документ с датой **25.08.2026** | запрет |

### 1.2. Кладовщик (N=5)

Под `Кладовщик` (складской документ / ордер, раздел «Складские операции»):

| Действие | Ожидание |
|---|---|
| Дата **28.08.2026** и позже | записывается |
| Дата **27.08.2026** и раньше | запрет |

Тот же пользователь **не** должен получить границу N=1: адресат — его группа.

### 1.3. Бухгалтер (N=30)

Под `Бухгалтер` (бухучёт / закрытие периода / любая проверка по организации):

| Действие | Ожидание |
|---|---|
| Дата **03.08.2026** и позже (в т.ч. август) | записывается **без заявки** |
| Дата **02.08.2026** и раньше (в т.ч. 01.07, июнь) | запрет — нужна заявка |

Это объясняет, зачем бухгалтеру заявка «с начала квартала»: III квартал начинается **01.07.2026**, а автограница бухгалтера — только с **03.08.2026**.

### 1.4. Сдвиг на следующий день

Дата сеанса 02.09.2026 (или сдвиг серверной даты на копии) → снова запуск задания.

| Адресат | Новая запись |
|---|---|
| Для всех | 01.09.2026 |
| Склады | 28.08.2026 |
| Бухгалтеры | 03.08.2026 |

### 1.5. Отчёт

Отчёт `нп_Действующие даты запрета (НП)`:

- три (или больше, если групп складов несколько) записи источника **«Автоматическая установка»** с верным N;
- нет источника «Временно открытый период».

### 1.6. Индивидуальная настройка не снимает запрет с остальных разделов

БСП выбирает адресата целиком. Если у Скрипко есть только запись «Касса / касса завода», поиск больше не смотрит группу и «для всех» — пропадают и общая дата, и другие комбинации родителя (например склад группы «Продажи»).

После задания в типовом РС у неё должен быть **полный набор родителя** плюс своя касса:

| Пользователь | Раздел | Объект | Дата | Смысл |
|---|---|---|---|---|
| Для всех пользователей | (пусто) | (пусто) | сегодня − 1 | как было |
| Скрипко Анастасия | Касса | касса завода | как в её настройке | исключение |
| Скрипко Анастасия | остальные комбинации родителя | как у родителя | как до кассы |

Родитель — кто был бы адресатом без личных записей (одна выигрывающая группа или «для всех»), не смесь групп.

- Не в группах с записями → набор «для всех» (пустая пара N=1).
- Выигрывает «Продажи» (склад N=5, своей общей даты нет) → сначала на группу копируется набор «для всех», затем пользователю: касса + склад «Продажи» + пустая пара N=1.
- Выигрывают «Бухгалтеры» (пустая пара N=30), даже если есть ещё «Продажи» со складом → только набор бухгалтеров N=30, склад «Продажи» **не** копируется (до кассы он тоже не действовал).

Под Скрипко:

| Документ | Ожидание |
|---|---|
| Касса этой кассы, дата внутри её N | записывается |
| Касса этой кассы, дата старше её границы | запрет |
| Комбинации, которые закрывал родитель до кассы (продажа, склад группы, банк, другая касса) | те же запреты, что до личной записи, **не** «можно всё» |

Если у пользователя уже есть своя пустая пара в регистре настроек или ручная общая дата — набор родителя не копируем (иначе появится склад группы, которого до детальной записи не было).

После **удаления или выключения** личной кассы один запуск задания снимает и кассу, и унаследованный набор родителя. Поиск снова идёт по группе / «для всех». Не ждать второго запуска.

## 2. Типовая заявка бухгалтера: все по организации с начала квартала на 3 дня

Бизнес-смысл: бухгалтеру нужно править документы `ОргА` с **01.07.2026**, на три дня согласования.

Поля документа:

| Реквизит | Значение |
|---|---|
| Пользователь (кому) | `Бухгалтер` **или** группа «Бухгалтеры» (если открыть всем бухгалтерам) |
| Открыть период с | **01.07.2026** |
| Срок действия, дней | **3** |
| Указывать | **По разделам и объектам** |
| Таблица | одна строка: объект = `ОргА`, раздел **пустой** |
| Причина | например: «Корректировка квартальной отчётности ОргА с 01.07» |

Пустой раздел при заполненной организации разворачивается в **18 записей** типового РС (все разделы организации, включая `УчетПоМСФО`). Не путать с пустой таблицей: пустая таблица — общая дата *адресата* на всю базу, не только `ОргА`.

Отсечка = 01.07.2026 − 1 день = **30.06.2026**.

### 2.1. Запись и печать до согласования

1. Под `Бухгалтер` создать и записать заявку (без полных прав). Регистр настроек и форма константы уведомлений **не видны**.
2. Ответственный = текущий пользователь, поле недоступно.
3. Команда печати **«Заявка на открытие периода»**: превью с номером, датой, кому, периодом с, K=3, строкой **Открывается: по разделам учёта и выбранным объектам** (не «Указывать / По разделам и объектам»), причиной, строкой `ОргА` (раздел может быть пустым / по разделам после разворота в печати — в макете строка таблицы: раздел и объект). Не страница «Печатная форма недоступна».
4. Скрепка **Файлы**: после печати появляется PDF «Заявка на открытие периода» (если запись файла не удалась — превью всё равно есть, ошибка в журнале).
5. Гиперссылка **Документооборот** в панели навигации — одна. «Начать обработку» — в «Создать на основании».
6. Типовой РС **ещё не изменился**. Документ `ОргА` от 01.07.2026 под бухгалтером по-прежнему запрещён.
7. После «Начать обработку» появляется связь с ДО: период с, срок, таблица и «кому» только просмотр **сразу**, даже если статус `На согласовании` в ERP ещё не пришёл. Правка отклоняется. Если отклонили (`Не согласован`) — поля снова доступны.

### 2.2. Согласование 01.09.2026

Отправить в ДО, согласовать **01.09.2026**.

**Ожидание:**

- состояние на форме заявки — согласован;
- заявка не редактируется (период с, срок, таблица, кому);
- в типовом РС по `ОргА` × 18 разделов × адресат заявки: дата **30.06.2026**;
- в `нп_СостояниеОткрытыхПериодов` те же комбинации: заявка-основание, окончание **03.09.2026**, `ДатаЗапретаДоОткрытия` = прежние 02.08.2026 (авто N=30);
- отчёт: эти строки — **«Временно открытый период»**, ответственный заполнен.

Под `Бухгалтер`:

| Документ | Ожидание |
|---|---|
| `ОргА`, дата **01.07.2026** и позже | записывается |
| `ОргА`, дата **30.06.2026** | запрет (день отсечки) |
| Другая организация, дата **01.07.2026** | запрет, если заявка была только на `ОргА` |

18 записей по `ОргА` делают бухгалтера адресатом БСП. Сразу при согласовании копируется набор родителя (группа «Бухгалтеры» N=30), иначе другая организация и касса остались бы без запрета. Заявку на пустую пару (общая дата адресата) набор родителя не копирует: адресат и так выбран своей общей датой.

Под `МенеджерПродаж` та же `ОргА` от 01.07: **запрет** — заявка открыла период другому адресату.

### 2.3. Задание не затирает открытый период

Ручной запуск задания 01.09, 02.09, 03.09: отсечка 30.06 на месте, состояние на месте, авто N=30 эту комбинацию не перезаписывает.

Остальные адресаты (для всех N=1, склады N=5) продолжают сдвигаться как в сценарии 1.4.

### 2.4. Возврат после K

Дата сеанса **04.09.2026**, запуск задания.

**Ожидание:**

- состояние по заявке удалено;
- по комбинациям `ОргА` для бухгалтера снова автограница дня запуска: **04.09 − 30 = 05.08.2026**;
- документ `ОргА` от 01.07.2026 снова **запрещён**;
- отчёт: снова «Автоматическая установка», N=30.

### 2.5. Досрочное закрытие (если период ещё действует)

Полные права, заявка с действующим состоянием → «Закрыть период досрочно» → Да.

Сразу (без задания): прежняя дата возвращена, состояние удалено. Если у адресата не осталось детальных настроек и других открытий — унаследованный набор родителя снимается сразу. Следующий запуск задания ставит текущий N. Пометка удаления заявки, пока состояние есть, запрещена.

## 3. Типовая заявка менеджеру продаж: на 1 день открыть 10 дней

Бизнес-смысл: менеджеру с N=1 нужно поправить продажи за последние 10 календарных дней, доступ нужен **один день**.

«10 дней включая сегодня» при D=01.09.2026: с **23.08.2026** по 01.09.2026.

| Реквизит | Значение |
|---|---|
| Пользователь (кому) | `МенеджерПродаж` |
| Открыть период с | **23.08.2026** |
| Срок действия, дней | **1** |
| Указывать | **По разделам и объектам** |
| Таблица | объект = `ОргА`, раздел = **Продажи** (узко) **или** объект = `ОргА`, раздел пустой (все 18 разделов организации) |
| Причина | «Исправление реализаций ОргА за последние 10 дней» |

Отсечка = 23.08 − 1 день = **22.08.2026**. Окончание при согласовании 01.09 = **01.09.2026**. Возврат заданием **02.09**.

Если нужны ровно «10 дней назад» без включения сегодня в отсчёт «назад» — `Период с` = 22.08.2026, отсечка 21.08. В причине написать, какой интервал имелся в виду.

### 3.1. До согласования

Документ продаж `ОргА` от 25.08 под менеджером — **запрет**. Типовой РС не менялся.

Печать и скрепка — как в 2.1.

### 3.2. После согласования 01.09

Под `МенеджерПродаж`:

| Документ | Ожидание |
|---|---|
| `ОргА` / продажи, дата **23.08.2026** … сегодня | записывается |
| дата **22.08.2026** | запрет |
| другая организация | запрет, если в заявке только `ОргА` |

Под `Бухгалтер` документы июля **не** открылись этой заявкой.

Задание 01.09 23:00 отсечку не трогает. Задание **02.09**: возврат к авто N=1 (запись 01.09.2026), продажи от 25.08 снова запрещены.

### 3.3. Заявка на группу менеджеров

Тот же сценарий, но «кому» = группа пользователей отдела продаж. Проверить двоих из группы: обоим доступен интервал; коллега не из группы — нет.

## 4. Форма, ДО, печать (на любой заявке)

| № | Шаг | Ожидание |
|---|---|---|
| 4.1 | Открыть новую заявку | страница «Основное»; нет связи с ДО — это декоратор состояния, не ошибка кнопки |

## 5. Граничные случаи на той же настройке

### 5.1. Пустая таблица = вся база адресата

Заявка: кому = бухгалтер, период с = 01.07, K=3, таблица пустая, раздел шапки пустой.

После согласования — **одна** типовая запись: пустой раздел, пустой объект, адресат бухгалтера, отсечка 30.06. Это открывает **все** разделы/объекты этому адресату, не только `ОргА`. Для целевой базы обычно **слишком широко**; основной путь — сценарий 2 (организация без раздела).

### 5.2. Несколько разделов без объектов

Способ «По разделам», две строки: «Бухгалтерский учёт» и «Регламентные операции». Отсечка — две общие даты раздела (объект = раздел) для адресата.

### 5.3. Пересечение двух заявок

Сначала согласована заявка сценария 2 (отсечка 30.06, окончание 03.09). Затем вторая по той же `ОргА` / тем же разделам / тому же адресату: период с 01.06, K=5 (отсечка 31.05, окончание 05.09).

Ожидание: действует **31.05**; окончание **05.09**; `ДатаЗапретаДоОткрытия` остаётся от **первого** открытия (02.08), вторая заявка её не затирает.

### 5.4. Права

`Бухгалтер` не открывает регистр настроек и форму константы уведомлений. «Закрыть период досрочно» на форме неактивно / не для него. `Админ` закрывает.

### 5.5. Отключение настройки

Снять «Включено» у N=1. Следующий успешный запуск задания автозапись «для всех» **удаляет**. Ручные даты в типовой форме по складу без настройки — задание не трогает.

### 5.6. Запись внутри закрытого периода

Любой из трёх пользователей, документ раньше своей автограницы, заявки нет: типовое сообщение БСП, формулировка не менялась.
