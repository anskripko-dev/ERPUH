# Расширение `нп_ДатыЗапретаИзменения`

Отдельное расширение по заявке **ERP.2026.14** (ред. 2): автоматическая установка дат запрета «сегодня минус N», заявка на открытие периода с согласованием в 1С:Документообороте 3, отчёт действующих дат.

Префикс: **`нп_`**. Назначение: **Customization** (адаптация). Синонимы собственных объектов метаданных — с суффиксом `(НП)` (формы, реквизиты и значения перечисления — без маркера). OpenSpec: `openspec/changes/np-dates-of-prohibition-setup/`.

После приёмки на тесте объекты переносятся в `uhnp.НП`, это расширение снимается. **Не** подключать одновременно с теми же объектами внутри НП.

```
Extensions/нп_ДатыЗапретаИзменения/
  README.md
  configurator/     ← выгрузка конфигуратора (Configuration.xml)
  tests/            ← проверки правил без ИБ 1С
```

Соответствие с основной конфигурацией — **по имени** (`KeepMapping…ByIDs = false`). EDT-проект для этого расширения не готовится.

## Состав

| Объект | Назначение |
|---|---|
| Подсистема `нп_ДатыЗапретаИзменения` | Командный интерфейс, картинка `нп_ДатыЗапретаИзменения16` |
| ОМ `нп_ДатыЗапретаИзменения` | Расчёт, запись типового РС, задание, открытие/возврат периода |
| `&После` `ПриИзмененииСостоянияСогласования` | Открытие периода после `Согласован` в ДО 3 |
| `&После` `ПриОпределенииНастроекПечати` | Регистрация заявки в объектах печати БСП — иначе ДО не видит печатную форму |
| Справочник `нп_ЗаявкаНаОткрытиеПериодаПрисоединенныеФайлы` | Хранение файлов заявки. Без него ДО 3 не забирает печатную форму как файл. Длина кода 0, ввод по строке — Наименование (не Код) |
| Определяемые типы БИД | Заявка в `ИнтеграцияС1СДокументооборотВсеСсылкиПереопределяемый` и `…ДокументыОбъектыПереопределяемый` — иначе её нет в правилах интеграции |
| РС `нп_НастройкиАвтоматическойУстановкиДатЗапрета` | Правила автоустановки (полные права). Скользящее / относительное / комбинированное. Пустые объект и раздел — общая дата адресата |
| РС `нп_СостояниеОткрытыхПериодов` | Действующие открытия по заявкам; в командном интерфейсе подсистемы |
| Документ `нп_ЗаявкаНаОткрытиеПериода` | Заявка; проведение запрещено. Пользователь и организация обязательны. Без таблицы разделов — общая дата этого адресата. Печатная форма `ЗаявкаНаОткрытиеПериода` и справочник `нп_ЗаявкаНаОткрытиеПериодаПрисоединенныеФайлы` для файла в ДО 3 |
| РЗ `нп_СдвигДатЗапретаИзменения` | Ежедневно 23:00: возврат истёкших, затем настройки |
| Константа `нп_ПолучателиУведомленийСдвигаДатЗапрета` | E-mail через `;`. Без стандартных команд: иначе дубль в «Сервис» с общей формой |
| Общая форма `нп_ФормаПолучателейУведомленийСдвигаДатЗапрета` | Единственная команда раздела «Сервис»; полные права |
| Отчёт `нп_ДействующиеДатыЗапрета` | Источник: авто / открытый период / вручную |
| Роль `нп_БазовыеПраваДатЗапрета` | Заявка, отчёт, чтение состояния — всем, у кого эта роль (это «базовые» заявки, пока расширение отдельно от НП). Настройки и константа не входят. Имя не `нп_БазовыеПрава`: такое уже есть в НП |
| Роль `нп_УказаниеРазделовИОбъектовЗаявки` | Маркер: таблица разделов и объектов на форме заявки. Полноправному таблица видна и без неё |
| Перечисление `нп_СпособыРасчетаДатыЗапрета` | Скользящее окно / относительная дата БСП / комбинированная |

Типовой РС `ДатыЗапретаИзменения` не расширяется: доработка только пишет и удаляет записи. Проверка `ПередЗаписью` БСП не меняется.

## Сборка `.cfe` и загрузка

1. В конфигураторе: Конфигурация → Расширения → создать расширение (адаптация, префикс `нп_`) **либо** открыть уже созданное `нп_ДатыЗапретаИзменения`.
2. Конфигурация → **Загрузить конфигурацию из файлов…** → каталог:

```
…/Extensions/нп_ДатыЗапретаИзменения/configurator
```

В корне каталога должен быть `Configuration.xml`.

Перед загрузкой в конфигуратор проверка структуры XML (XSD MDClasses 2.20, без ИБ 1С):

```
python3 Extensions/нп_ДатыЗапретаИзменения/tests/validate_dump_xml.py
python3 Extensions/нп_ДатыЗапретаИзменения/tests/test_rules.py
```

В Cursor на ПК для `verify_xml` нужен MCP `1c-code-metadata-mcp` (`http://localhost:8000/mcp`) — Docker OneRPA с `LICENSE_KEY`. Уже подключённый `1c-syntax-checker-mcp` на `:8002` проверяет только BSL, не дамп метаданных.

3. Обновить конфигурацию БД расширения, включить расширение.
4. Для поставки: Конфигурация → Расширения → сохранить как `нп_ДатыЗапретаИзменения.cfe`.

Не подключать этот пакет одновременно с теми же объектами в `uhnp.НП` (дубли имён).

## Первый запуск на копии ИБ

1. Загрузить расширение **отдельным** расширением, рядом с НП, не внутрь НП.
2. Включить функциональные опции дат запрета по разделам / объектам / пользователям, если нужны детальные записи.
3. Заполнить константу получателей уведомлений общей формой из подсистемы (полные права). Пустая константа или неучтённая почта — только журнал `нп_СдвигДатЗапретаИзменения`.
4. Сверить текущий типовой РС **до** включения задания (ручные общие даты адресатов перекрывают детальные записи того же адресата; задание их не удалит).
5. Заполнить настройки автоустановки. Пустые объект и раздел — общая дата адресата. Типовую форму для той же политики не использовать: ручная запись по той же комбинации останется и может перекрыть автоустановку. В заявке пользователя/группу оставить пустыми нельзя.
6. Включить регламентное задание (расписание уже 23:00). Первый прогон лучше выполнить вручную на копии.
7. В ДО 3 завести вид документа и правило интеграции для `нп_ЗаявкаНаОткрытиеПериода`. Документ должен быть в списке объектов ИС (после загрузки расширения — обновить конфигурацию БД расширения и перезапустить сеанс: список типов кэшируется). Если проверка применения ругается на определяемые типы БИД («контролируемое свойство Тип не совпадает») — не жать «Исправить»: это затрёт наш тип. В дампе у `Тип` стоит `Extended`, состав основной конфигурации не подменяется. То же для `ВладелецПрисоединенныхФайлов` и `ПрисоединенныйФайл`. В правиле интеграции присоединить печатную форму **«Заявка на открытие периода»** (идентификатор `ЗаявкаНаОткрытиеПериода`) и перенос присоединенных файлов ИС. Печать на форме добавляют `ПодключаемыеКоманды`. Скрепка **Файлы** в командной панели — `РаботаСФайлами.ПриСозданииНаСервере`. Страница **Основное** — `Pages` с `PagesRepresentation=None`. Гиперссылка **Документооборот** в панели навигации — своя общая команда `нп_Документооборот` (группа `CommandGroup.Документооборот`, тип параметра `DocumentRef.нп_ЗаявкаНаОткрытиеПериода`, обработчик как у типовой `ИнтеграцияС1СДокументооборот`). Платформа сажает её сама; в `CommandInterface` формы её добавлять нельзя — получится дубль. Типовую общую команду на native-документ расширения посадить нельзя: её `ТипПараметраКоманды` — контролируемое свойство, расширение состава даёт «не совпадает со значением в расширяемой конфигурации». Не жать «Исправить» по этим двум командам — загрузить дамп без правки `CommandParameterType`. Назначить типовую команду кнопке командной панели через `ИмяКоманды` нельзя — группа `FormNavigationPanel`. Команду БИД «Файлы» на форме документа скрывает `&После` `ПриОпределенииНеобходимостиВыводитьКомандуПрисоединенныхФайловДО` — иначе при правиле интеграции она встаёт рядом со скрепкой БСП. «Начать обработку» — подключаемая команда создания на основании (`СозданиеНаОснованииПереопределяемый`). Менеджер печати при выводе формы пишет PDF в присоединенные файлы — иначе ДО не получит файл. Запись PDF обёрнута в `Попытка`: если файл не создался, превью БСП всё равно показывает форму (иначе пустой табличный документ → «Печатная форма недоступна»). Если макет `ПФ_MXL_…` не читается, печать собирается без него. Все реквизиты и табличные части в документ ДО переносить не нужно — согласующие видят сведения из файла.
8. Роль `нп_БазовыеПраваДатЗапрета` — на всех, кому нужна заявка (общий профиль). Это «базовые» заявки этого расширения: настройки и константа не входят. В типовой раздел «НСИ и администрирование → НСИ» документ без заимствования `Subsystem.Администрирование.Subsystem.НСИ` не попадает; заявка в своей подсистеме «Даты запрета изменения (НП)». Имя роли не `нп_БазовыеПрава`, пока расширение живёт рядом с НП.

Откат: снять расширение. Записи типового РС остаются последними абсолютными датами.

## Перенос в НП после теста

1. Перенести объекты в `uhnp.НП` (префикс `нп_` уже стоит).
2. Права `нп_БазовыеПраваДатЗапрета` влить в роль `нп_БазовыеПрава` НП — заявка станет доступна всем с базовыми правами НП, отдельную роль не назначать.
3. Если заявка должна стоять в типовом разделе НСИ — добавить документ в состав `Администрирование.НСИ` уже в НП, не заимствуя подсистему в это отдельное расширение.
4. Снять отдельное расширение с ИБ.

## Норматив расчёта N

N — число последних календарных дней **включая текущий**. В типовой ресурс пишется дата без времени: `НачалоДня(дата сеанса) − N`. Документ в день границы запрещён.

| N | Дата запуска | Запись | Доступно с |
|---|---|---|---|
| 0 | 20.08.2026 | 20.08.2026 | 21.08.2026 |
| 1 | 20.08.2026 | 19.08.2026 | 20.08.2026 |
| 5 | 20.08.2026 | 15.08.2026 | 16.08.2026 |

«Для всех пользователей» → `Перечисление.ВидыНазначенияДатЗапрета.ДляВсехПользователей`. Общая дата раздела → `Объект = Раздел` (ПВХ). Организация без раздела разворачивается в 18 разделов, включая `УчетПоМСФО`. Если у пользователя в этом запуске есть детальные настройки или действующее детальное открытие по заявке, копируется полный набор родителя (группа или «для всех»), иначе БСП не применяет запреты родителя к остальным комбинациям. Согласование заявки копирует набор сразу; удаление настройки или закрытие открытия снимает его сразу / тем же запуском.

## Приёмка на живой ИБ

Сценарии под **целевую настройку** базы (всем N=1, складам N=5, бухгалтерам N=30; заявка бухгалтера с начала квартала; менеджеру на 1 день открыть 10 дней) — `tests/сценарии-тестирования.md`.

Сценарии §5 заявки (1–20, 7а–7г, 8а, 12а) в этой среде выполнить нельзя: нет конфигуратора 1С и информационной базы. Чеклист — `openspec/changes/np-dates-of-prohibition-setup/tasks.md`, раздел 7. Правила расчёта и состав метаданных проверяются скриптом `tests/test_rules.py`.
