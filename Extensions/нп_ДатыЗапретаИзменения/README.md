# Расширение `нп_ДатыЗапретаИзменения`

Отдельное расширение по заявке **ERP.2026.14** (ред. 2): автоматическая установка дат запрета «сегодня минус N», заявка на открытие периода с согласованием в 1С:Документообороте 3, отчёт действующих дат.

Префикс: **`нп_`**. Назначение: **Customization** (адаптация). OpenSpec: `openspec/changes/np-dates-of-prohibition-setup/`.

После приёмки на тесте объекты переносятся в `uhnp.НП`, это расширение снимается. **Не** подключать одновременно с теми же объектами внутри НП.

```
Extensions/нп_ДатыЗапретаИзменения/
  README.md
  configurator/     ← выгрузка конфигуратора (Configuration.xml)
  tests/            ← проверки правил без ИБ 1С
```

Соответствие с основной конфигурацией — **по имени** (`KeepMapping…ByIDs = false`). EDT-проект для этого расширения не готовится.

## Состав

| Объект | Назначение |
|---|---|
| Подсистема `нп_ДатыЗапретаИзменения` | Командный интерфейс; служебный РС состояния в составе, без стандартных команд |
| ОМ `нп_ДатыЗапретаИзменения` | Расчёт, запись типового РС, задание, открытие/возврат периода |
| `&После` `ПриИзмененииСостоянияСогласования` | Открытие периода после `Согласован` в ДО 3 |
| РС `нп_НастройкиАвтоматическойУстановкиДатЗапрета` | Правила автоустановки (полные права) |
| РС `нп_СостояниеОткрытыхПериодов` | Служебный: прежняя граница и срок открытого периода |
| Документ `нп_ЗаявкаНаОткрытиеПериода` | Заявка; проведение запрещено |
| РЗ `нп_СдвигДатЗапретаИзменения` | Ежедневно 23:00: возврат истёкших, затем настройки |
| Константа `нп_ПолучателиУведомленийСдвигаДатЗапрета` | E-mail через `;`, форма константы |
| Отчёт `нп_ДействующиеДатыЗапрета` | Источник: авто / открытый период / вручную |
| Роль `нп_БазовыеПрава` | Заявка, отчёт, чтение состояния; **без** настроек и константы |

Типовой РС `ДатыЗапретаИзменения` не расширяется: доработка только пишет и удаляет записи. Проверка `ПередЗаписью` БСП не меняется.

## Сборка `.cfe` и загрузка

1. В конфигураторе: Конфигурация → Расширения → создать расширение (адаптация, префикс `нп_`) **либо** открыть уже созданное `нп_ДатыЗапретаИзменения`.
2. Конфигурация → **Загрузить конфигурацию из файлов…** → каталог:

```
…/Extensions/нп_ДатыЗапретаИзменения/configurator
```

В корне каталога должен быть `Configuration.xml`.

Перед загрузкой в конфигуратор проверка структуры XML (XSD MDClasses 2.20, без ИБ 1С):

```
python3 Extensions/нп_ДатыЗапретаИзменения/tests/validate_dump_xml.py
python3 Extensions/нп_ДатыЗапретаИзменения/tests/test_rules.py
```

В Cursor на ПК для `verify_xml` нужен MCP `1c-code-metadata-mcp` (`http://localhost:8000/mcp`) — Docker OneRPA с `LICENSE_KEY`. Уже подключённый `1c-syntax-checker-mcp` на `:8002` проверяет только BSL, не дамп метаданных.

3. Обновить конфигурацию БД расширения, включить расширение.
4. Для поставки: Конфигурация → Расширения → сохранить как `нп_ДатыЗапретаИзменения.cfe`.

Не подключать этот пакет одновременно с теми же объектами в `uhnp.НП` (дубли имён).

## Первый запуск на копии ИБ

1. Загрузить расширение **отдельным** расширением, рядом с НП, не внутрь НП.
2. Включить функциональные опции дат запрета по разделам / объектам / пользователям, если нужны детальные записи.
3. Заполнить константу получателей уведомлений формой константы (полные права). Пустая константа или неучтённая почта — только журнал `нп_СдвигДатЗапретаИзменения`.
4. Сверить текущий типовой РС **до** включения задания (общие даты адресатов перекрывают детальные записи того же адресата).
5. Заполнить настройки автоустановки. Пустые объект **и** раздел одновременно записывать нельзя.
6. Включить регламентное задание (расписание уже 23:00). Первый прогон лучше выполнить вручную на копии.
7. В ДО 3 завести вид документа и правило интеграции для `нп_ЗаявкаНаОткрытиеПериода` (вне объёма разработки).
8. Роль `нп_БазовыеПрава` этого расширения — на пользователей, которые создают заявки и смотрят отчёт. Регистр настроек и константа им недоступны.

Откат: снять расширение. Записи типового РС остаются последними абсолютными датами.

## Перенос в НП после теста

1. Перенести объекты в `uhnp.НП` (префикс `нп_` уже стоит).
2. Права `нп_БазовыеПрава` влить в одноимённую роль НП, если она есть.
3. Снять отдельное расширение с ИБ.

## Норматив расчёта N

N — число последних календарных дней **включая текущий**. В типовой ресурс пишется дата без времени: `НачалоДня(дата сеанса) − N`. Документ в день границы запрещён.

| N | Дата запуска | Запись | Доступно с |
|---|---|---|---|
| 0 | 20.08.2026 | 20.08.2026 | 21.08.2026 |
| 1 | 20.08.2026 | 19.08.2026 | 20.08.2026 |
| 5 | 20.08.2026 | 15.08.2026 | 16.08.2026 |

«Для всех пользователей» → `Перечисление.ВидыНазначенияДатЗапрета.ДляВсехПользователей`. Общая дата раздела → `Объект = Раздел` (ПВХ). Организация без раздела разворачивается в 18 разделов, включая `УчетПоМСФО`.

## Приёмка на живой ИБ

Сценарии §5 заявки (1–20, 7а–7г, 8а, 12а) в этой среде выполнить нельзя: нет конфигуратора 1С и информационной базы. Чеклист — `openspec/changes/np-dates-of-prohibition-setup/tasks.md`, раздел 7. Правила расчёта и состав метаданных проверяются скриптом `tests/test_rules.py`.
