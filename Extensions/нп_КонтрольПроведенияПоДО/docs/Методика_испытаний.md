# Методика испытаний

**Наименование:** Контроль проведения документов по согласованию в 1С:Документооборот  
**Расширение:** `нп_КонтрольПроведенияПоДО`  
**Цель:** проверка функциональности контроля проведения, пересогласования и настроек применимости

---

## 1. Краткая функциональность

| № | Возможность | Ожидаемое поведение |
|---|---|---|
| 1 | Запрет проведения без согласования | Документ с включённым контролем проводится только при состоянии ДО «Согласован» |
| 2 | Дата начала действия | Документы с датой раньше порога проводятся без требования согласования |
| 3 | Отбор по реквизитам (СКД) | Контроль только для документов, удовлетворяющих отбору |
| 4 | Участники (включая/исключая) | Контроль применяется к указанным пользователям/группам; исключение имеет приоритет |
| 5 | Статус на форме | На форме контролируемого документа отображается состояние согласования ДО |
| 6 | Существенные изменения | При изменении «неразрешённых» реквизитов — вопрос; при согласии — прерывание и новый запуск обработки ДО |
| 7 | Белый список реквизитов | Изменение только разрешённых реквизитов не вызывает пересогласование |
| 8 | Проведение без правок | Согласованный записанный документ проводится без повторного запуска согласования |

---

## 2. Предварительные условия

1. В информационной базе установлено и включено расширение `нп_КонтрольПроведенияПоДО` (загрузка из `.cfe` или выгрузки `configurator`).  
2. Не подключены одновременно этот пакет и дублирующие объекты `uhnp.НП`.  
3. Включены константы интеграции и согласования через 1С:Документооборот; настроена связь с ДО 3.  
4. Для пилотного типа настроено правило интеграции документа с ДО (типовой контур БИД).  
5. Есть тестовая организация, пользователи/группы для проверки отбора участников.  
6. Есть доступ к форме записи регистра **«Настройки контроля проведения по ДО»**.

---

## 3. Настройки для запуска испытаний

### 3.1. Настройка контроля (обязательно)

Регистр сведений **«Настройки контроля проведения по ДО»** — новая запись:

| Поле | Рекомендуемое значение для пилота |
|---|---|
| Полное имя объекта метаданных | `Документ.ПеремещениеТоваров` (выбор из списка) |
| Организация | тестовая организация |
| Контролировать проведение | Да |
| Дата начала действия | дата внедрения / начало периода испытаний |
| Отбор по реквизитам | пусто (= все документы типа) либо тестовое условие |
| Пользователи (включая/исключая) | пусто (= все) либо тестовые строки |

Программная установка пилотной настройки (при необходимости):

```bsl
нп_КонтрольПроведенияПоСогласованиюДО.УстановитьНастройкуПоУмолчаниюДляПеремещенияТоваров(
	Организация, ДатаНачалаДействия);
```

После изменения настроек при необходимости обновить повторно используемые значения (перезапуск сеанса или `ОбновитьПовторноИспользуемыеЗначения()`).

### 3.2. Белый список (для сценариев 6–7)

Регистр сведений **«Разрешённые реквизиты при согласовании ДО»**:

- для того же типа и организации добавить, например, `Комментарий`;
- остальные реквизиты / колонки ТЧ остаются «существенными».

### 3.3. Отбор участников (для сценария 4)

В таблице пользователей настройки:

| Включая/Исключая | Участник | Смысл |
|---|---|---|
| Включая | группа или пользователь | контроль применяется |
| Исключая | пользователь из группы | контроль не применяется даже при вхождении во включающую группу |

Пустая таблица = контроль для всех пользователей (при прочих условиях).

## 4. Сценарии испытаний

### 4.1. Запрет проведения без согласования

**Шаги:** создать перемещение по тестовой организации с датой ≥ порога; не отправлять / не доводить до «Согласован»; выполнить проведение.  
**Ожидание:** отказ с текстом вида «Проведение документа невозможно. Печатная форма "Накладная на перемещение" не согласована в системе Документооборот.»

### 4.2. Проведение после согласования

**Шаги:** отправить документ в ДО; дождаться состояния «Согласован»; провести **без изменения** реквизитов.  
**Ожидание:** проведение успешно; повторный запуск обработки ДО не выполняется.

### 4.3. Дата раньше порога

**Шаги:** документ с датой < `ДатаНачалаДействия`; провести без согласования.  
**Ожидание:** контроль не применяется, проведение допускается (при прочих типовых ограничениях).

### 4.4. Отбор участников

**Шаги:** настроить «Включая» группу А и «Исключая» пользователя Б из группы А.  
**Ожидание:** пользователь из А (не Б) — контроль действует; пользователь Б — контроль не действует.

### 4.5. Существенные изменения после согласования

**Шаги:** документ в состоянии «Согласован» (или «На согласовании»); изменить реквизит **не** из белого списка; записать.  
**Ожидание:** вопрос подтверждения; при «Да» — прерывание и новый запуск обработки в ДО; провести можно только после нового «Согласован»; при «Нет» — запись отменена.

### 4.6. Только разрешённые реквизиты

**Шаги:** изменить только реквизит из белого списка; записать / провести.  
**Ожидание:** вопроса о пересогласовании нет; обработка ДО не перезапускается; проведение при «Согласован» допускается.

### 4.7. Проведение уже проведённого после существенных правок

**Шаги:** согласованный проведённый документ; существенное изменение; подтвердить запись.  
**Ожидание:** документ распроведён; ДО перезапущен; проведение снова только после нового согласования.

### 4.8. Статус на форме

**Шаги:** открыть форму контролируемого документа со связью с ДО.  
**Ожидание:** отображается представление состояния согласования.

### 4.9. Отчёт (при наличии)

**Шаги:** открыть отчёт `нп_СогласованныеНеПроведенныеПеремещения`.  
**Ожидание:** в выборку попадают согласованные и не проведённые перемещения по условиям отчёта.

---

## 5. Критерии приёмки

Испытания считаются успешными, если:

1. без «Согласован» проведение контролируемого документа невозможно;  
2. после «Согласован» проведение без правок проходит без пересогласования;  
3. существенные изменения вызывают подтверждение и перезапуск ДО;  
4. белый список и отборы (реквизиты / участники / дата) работают согласно настройке;  
5. отсутствуют ложные перезапуски согласования при проведении неизменённого документа.
