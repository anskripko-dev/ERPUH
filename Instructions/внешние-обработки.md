# Паттерн внешней обработки (БСП)

Инструкция для **внешних обработок** (`.epf`) в кастомизации **1С:ERP. Управление холдингом**: виды «Дополнительная обработка», «Заполнение объекта», «Создание связанных объектов».

Печатные формы сюда **не входят** — у них отдельный API (`Печать`, `Модификатор = ПечатьMXL`). Примеры ПФ: `ExternalDataProcessors/тн_ПФ_*`.

Исходники обработок — в `ExternalDataProcessors/` этого репозитория. Регистрация — через справочник «Дополнительные отчёты и обработки», без встраивания в типовую конфигурацию.

Шаблон: `ExternalDataProcessors/_Шаблон_ВнешняяОбработка`.

---

## Когда внешняя обработка, а когда нет

| Задача | Решение |
|--------|---------|
| Сервисная операция, пакетная обработка, мастер с формой | Внешняя **дополнительная обработка** |
| Кнопка в меню «Заполнить» документа/справочника | Вид **Заполнение объекта** |
| Ввод связанных объектов из меню «Создать на основании» | Вид **Создание связанных объектов** |
| Постоянная бизнес-логика объекта (проведение, реквизиты, подписки) | Расширение (`uhnp.НП` / `uhnp.ТН`) |
| Печатная форма | Внешняя ПФ (другой паттерн) |

---

## Виды обработок (не ПФ)

| Вид | Где команда | Назначение / разделы | Типичный тип команды |
|-----|-------------|----------------------|----------------------|
| `ВидОбработкиДополнительнаяОбработка()` | «Дополнительные обработки» в разделах интерфейса | **Разделы** (подсистемы) | Открытие формы / серверный метод / клиентский |
| `ВидОбработкиЗаполнениеОбъекта()` | меню «Заполнить» формы объекта/списка | **Назначение** (`Документ.*`, `Справочник.*`) | Открытие формы / серверный / клиентский |
| `ВидОбработкиСозданиеСвязанныхОбъектов()` | «Создать на основании» → связанные объекты | **Назначение** | Открытие формы / серверный / клиентский |

Виды и типы команд — **только** через `ДополнительныеОтчетыИОбработкиКлиентСервер.*()`, не строковыми литералами.

---

## Типы команд и точки входа

| Тип команды | Поведение | Что реализовать |
|-------------|-----------|-----------------|
| `ТипКомандыОткрытиеФормы()` | Открывается форма обработки | Форма + логика на форме / вызов модуля объекта |
| `ТипКомандыВызовСерверногоМетода()` | Сразу сервер, без UI; можно **расписание** | `ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполнения)` в модуле объекта |
| `ТипКомандыВызовКлиентскогоМетода()` | Клиент без открытия формы обработки | Клиентский экспортный обработчик по правилам БСП выбранной версии |
| `ТипКомандыЗагрузкаДанныхИзФайла()` | Только для **доп. обработки**; нужен подсистема загрузки из файла | По API подсистемы загрузки |

Одна обработка может объявить **несколько команд** с разными идентификаторами и типами.

```
ExternalDataProcessors/
└── <ИмяОбработки>/
    ├── README.md
    ├── <ИмяОбработки>.xml
    └── <ИмяОбработки>/
        ├── Ext/
        │   └── ObjectModule.bsl      # СведенияОВнешнейОбработке + ВыполнитьКоманду (если нужно)
```

## `СведенияОВнешнейОбработке()` — каркасы

### 1. Дополнительная обработка (разделы)

```bsl
Функция СведенияОВнешнейОбработке() Экспорт
	
	ПараметрыРегистрации = ДополнительныеОтчетыИОбработки.СведенияОВнешнейОбработке("3.1.10.359");
	ПараметрыРегистрации.Вид = ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработкиДополнительнаяОбработка();
	ПараметрыРегистрации.Версия = "1.0.0";
	ПараметрыРегистрации.Наименование = НСтр("ru = '...'");
	ПараметрыРегистрации.Информация = НСтр("ru = '...'");
	ПараметрыРегистрации.БезопасныйРежим = Ложь; // если нужны файлы, COM, привилегированный режим, «опасные» API
	
	// Где показывать в интерфейсе (не путать с Назначение у объектных видов)
	ПараметрыРегистрации.Разделы.Добавить(
		ДополнительныеОтчетыИОбработкиКлиентСервер.ИдентификаторРазделаДополнительныхОбработок());
	// Либо конкретная подсистема конфигурации — по принятому в проекте способу БСП.
	
	Команда = ПараметрыРегистрации.Команды.Добавить();
	Команда.Представление = НСтр("ru = '...'");
	Команда.Идентификатор = "Основная";
	Команда.Использование = ДополнительныеОтчетыИОбработкиКлиентСервер.ТипКомандыОткрытиеФормы();
	Команда.ПоказыватьОповещение = Ложь;
	
	Возврат ПараметрыРегистрации;
	
КонецФункции
```

### 2. Заполнение объекта

```bsl
ПараметрыРегистрации.Вид = ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработкиЗаполнениеОбъекта();
ПараметрыРегистрации.Назначение.Добавить("Документ.ЗаказКлиента");
// Разделы для этого вида обычно не заполняют — команда на формах объектов назначения.
```

### 3. Создание связанных объектов

```bsl
ПараметрыРегистрации.Вид = ДополнительныеОтчетыИОбработкиКлиентСервер.ВидОбработкиСозданиеСвязанныхОбъектов();
ПараметрыРегистрации.Назначение.Добавить("Документ.ЗаказКлиента");
```

### 4. Серверная команда с расписанием

```bsl
Команда.Использование = ДополнительныеОтчетыИОбработкиКлиентСервер.ТипКомандыВызовСерверногоМетода();
Команда.ПоказыватьОповещение = Истина;
// После регистрации в ИБ у команды появляются настройки расписания (регламент).
```

Версию БСП в `СведенияОВнешнейОбработке("X.Y.Z.W")` брать из актуальной конфигурации / соседних обработок проекта.

## `ВыполнитьКоманду` (серверный метод)

Обязательна для `ТипКомандыВызовСерверногоМетода`. Сигнатура модуля объекта:

```bsl
Процедура ВыполнитьКоманду(ИдентификаторКоманды, ПараметрыВыполнения) Экспорт
	
	Если ИдентификаторКоманды = "Основная" Тогда
		// ПараметрыВыполнения.ДополнительнаяОбработкаСсылка
		// ПараметрыВыполнения.ОбъектыНазначения — для заполнения / связанных (массив ссылок)
		ВыполнитьОсновнуюЛогику(ПараметрыВыполнения);
	Иначе
		ВызватьИсключение НСтр("ru = 'Неизвестная команда внешней обработки.'");
	КонецЕсли;
	
КонецПроцедуры
```

Особенности:

- Для **доп. обработки** объекты назначения часто пусты — логика самостоятельная.
- Для **заполнения / связанных** опираться на `ПараметрыВыполнения.ОбъектыНазначения` (несколько выделенных в списке — норма).
- Настройки с формы (если команда открывала форму и писала в `ХранилищеНастроек`) читать через `ДополнительнаяОбработкаСсылка`.
- Не оставлять «тихий» no-op на неизвестный идентификатор без явной политики.

## Форма обработки: параметры БСП

При `ТипКомандыОткрытиеФормы` БСП передаёт в форму:

| Параметр / реквизит | Назначение |
|---------------------|------------|
| `ДополнительнаяОбработкаСсылка` | Элемент `Справочник.ДополнительныеОтчетыИОбработки` |
| `ОбъектыНазначения` | Массив ссылок (заполнение / связанные; при открытии из списка — несколько) |
| `ИдентификаторКоманды` | Какая команда открыла форму (если несколько) |

Рекомендуемые реквизиты формы:

- `ДополнительнаяОбработкаСсылка` — тип `СправочникСсылка.ДополнительныеОтчетыИОбработки`
- при объектных видах — таблица/список объектов назначения или один основной объект

```bsl
&НаСервере
Процедура ПриСозданииНаСервере(Отказ, СтандартнаяОбработка)
	
	Если Параметры.Свойство("ДополнительнаяОбработкаСсылка") Тогда
		ДополнительнаяОбработкаСсылка = Параметры.ДополнительнаяОбработкаСсылка;
	КонецЕсли;
	
	Если Параметры.Свойство("ОбъектыНазначения") Тогда
		ОбъектыНазначения.ЗагрузитьЗначения(Параметры.ОбъектыНазначения);
	КонецЕсли;
	
	ВосстановитьНастройкиИзХранилища();
	
КонецПроцедуры
```

### `ХранилищеНастроек`

У элемента справочника доп. обработок есть `ХранилищеНастроек` (`ХранилищеЗначения`) — переживает сеансы, доступно с сервера.

Типовой цикл:

1. При открытии — прочитать структуру настроек и заполнить реквизиты формы.
2. Перед длительной серверной работой / при закрытии — записать структуру обратно в объект справочника.
3. В `ВыполнитьКоманду` — снова прочитать, если серверная команда должна использовать те же настройки.

Не путать с временным хранилищем платформы.

## Безопасный режим

| `БезопасныйРежим` | Ограничения |
|-------------------|-------------|
| `Истина` (по умолчанию предпочтительно) | Нет привилегированного режима, COM/DLL, произвольного доступа к файлам и интернету |
| `Ложь` | Нужны внешние ресурсы / «опасные» вызовы — **обязательно** указать причину в README |

Альтернатива полному отключению — разрешения БСП на конкретные ресурсы (если достаточно для сценария).

## Регистрация и публикация

1. Собрать `.epf` (Конфигуратор: открыть XML → Сохранить как `.epf`).
2. **НСИ и администрирование → … → Дополнительные отчёты и обработки** — создать / обновить элемент, загрузить файл.
3. Проверить **вид**, **назначение** или **разделы**, команды, публикацию («Использовать» / отладка).
4. Для серверных команд — при необходимости настроить **расписание**.
5. Права: пользователям нужна возможность открывать доп. обработки / соответствующие роли БСП.

Отладка без регистрации: **Файл → Открыть** → `.epf` (параметры БСП не передаются — закладывать ручной ввод объектов/настроек на форме).

Откат: снять публикацию / удалить элемент. Конфигурация не меняется.

## Антипаттерны

- Путать **доп. обработку** с **печатной формой** (другой вид и другой API)
- Заполнять только `Назначение` у доп. обработки без **Разделов** (команда не появится в ожидаемом месте интерфейса)
- Строки `"ДополнительнаяОбработка"` / `"ОткрытиеФормы"` вместо функций клиент-серверного модуля
- Серверная команда без `ВыполнитьКоманду` или с другим именем экспортной процедуры
- Игнор `ОбъектыНазначения` при вызове из списка (обработка только «текущей» строки)
- `БезопасныйРежим = Ложь` «на всякий случай» без обоснования
- Бизнес-логика, которая должна жить в расширении, спрятанная во внешнюю обработку без причины
